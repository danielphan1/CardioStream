## Decisions Made
- `cancel()` deliberately does NOT call `recRef.current?.abort()`, touch `armedRef`, or call `clearRestartTimer()` — unlike `stop()`, it leaves the live continuous recognizer session running exactly as-is, since the design intent is "give up waiting for a reply," not "end the voice session"
- Reusing `--cat-normal`/`--cat-chip-text` on the mic button is treated as an extension of an already-established token meaning (this same component already uses `--cat-normal` for its listening ring and live-transcript text), not a new use of a locked clinical color — no token's underlying hex value changed anywhere in the diff (verified via `git diff | grep -- '--cat-|--line-|--ref-'`)
- The Cancel button carries no `disabled` attribute by design — it is only rendered while `anyWorking` is true, which is what makes it a genuine escape hatch rather than another control that could itself get stuck
