<objective>
Fix the two P2 findings from the `/impeccable polish` + `/impeccable harden` design-review pass on
the main dashboard (`.impeccable/critique/2026-08-27T08-27-13Z__frontend-src-app-tsx.md`):
(1) the mic button's icon/fill only distinguishes the fatal "paused" state -- every other state
(off, listening, triggered, working, speaking) renders the identical ink-bordered/foam-filled
button, so a hands-free user has no way to see "armed and listening" versus "off" from the control
itself; (2) both the text-submit path and the voice path lock all controls for the full
`/agent` round-trip with no way out, which -- since the production agent is at $0 credits -- means
every real command today experiences a full lockout before resolving to "didn't understand."

This plan implements the fix exactly as specified by the design pass: an `armed` fill on the mic
button reusing the already-established `--cat-normal`/`--cat-chip-text` "listening" tokens, and a
visible, always-enabled Cancel control during the working state for both the text and voice paths,
guarded by seq-number supersede logic so a late reply after Cancel cannot resurrect stale state.

Purpose: give the app's one hands-free control surface an honest visibility-of-system-status signal
and a real user-control-and-freedom escape hatch, both scored 3/4 in the critique specifically
because of these two gaps.

Output: `cancel()` added to `useVoiceCommand.ts`; mic-armed styling, a Cancel button, and a
text-path seq guard added to `CommandBar.tsx`; 2 new hook tests + 4 new component tests --
committed in one commit.
</objective>
