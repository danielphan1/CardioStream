# Phase quick-260827-2v2: Fix ReadingsTable Category Column Clipping Summary

**ReadingsTable reflows to stacked cards (dl/dt/dd inside role="listitem") below 640px instead of clipping the Category column, gated by a new pure `shouldUseCardLayout` width predicate reusing the `useElementWidth` hook already shipped for BPTimeline/PulseTrend.**

## Accomplishments
- Fixed the P1 impeccable-critique finding: the clinically-most-important "Category" column no longer clips off-screen below ~640px with no way to reach it (no scroll/drag path was acceptable given the primary user's hand-mobility constraints)
- Added `shouldUseCardLayout(width)` — a pure, independently-tested breakpoint predicate with zero React/DOM imports, following the exact convention of `chartData.ts`'s `isDotCrowded`
- `ReadingsTable` now measures its own live container width (not viewport) via the pre-existing `useElementWidth` hook and conditionally renders a new `ReadingCard` component (stacked `dl`/`dt`/`dd` list, `role="listitem"`) below 640px, while the original 6-column table renders unchanged at desktop widths
- Zero regressions: all 6 pre-existing `ReadingsTable.test.tsx` tests pass completely unmodified (jsdom's always-0 measured width naturally exercises the table branch)

## Decisions Made
- Reused the project's existing 640px Tailwind `sm` breakpoint (StatsStrip's `sm:grid-cols-2` precedent, DESIGN.md's breakpoint scale) instead of introducing a new cutover value
- `shouldUseCardLayout(0)` deliberately returns `false` ("not yet measured") both to avoid a layout flash in the browser and to keep the pre-existing `ReadingsTable.test.tsx` suite passing with zero modifications (jsdom's ResizeObserver stub always reports width 0)
- All `ReadingCard` text uses `text-lg` (matching `ReadingRow`'s existing table-cell sizing), per CLAUDE.md's non-negotiable ≥18px body-font accessibility floor
