<objective>
Fix the P1 finding from the 2026-08-27 impeccable design critique of `frontend/src/App.tsx`: `ReadingsTable`'s rightmost "Category" column — clinically the most important field — gets clipped off-screen below ~640px width, with no way to reach it (a horizontal-scroll fix was explicitly rejected: it would require a swipe/drag gesture, which the project's primary user, a C4 quadriplegic with no reliable hand mobility, cannot reliably perform, and CLAUDE.md's accessibility constraints hard-ban drag interactions anywhere in the product).

Purpose: Below 640px, reflow the same 6 fields (Date, Time, AM/PM, Blood pressure, Pulse, Category) from a `<table>` into a stacked card-per-reading list, using the container's live measured width (not a CSS media query) so the same component works identically in tests (jsdom width=0 → table) and in the browser (real narrow width → cards).

Output:
- `frontend/src/lib/responsive.ts` — new pure predicate `shouldUseCardLayout(width): boolean`, no React/DOM imports.
- `frontend/src/lib/responsive.test.ts` — 5 unit tests locking its boundary behavior.
- `frontend/src/components/ReadingsTable.tsx` — replaced in place: same sort/slice/pagination/notes-guard logic, byte-for-byte unchanged, now with a `cardLayout` branch rendering a new `ReadingCard` component instead of `<table>` below 640px.
</objective>
