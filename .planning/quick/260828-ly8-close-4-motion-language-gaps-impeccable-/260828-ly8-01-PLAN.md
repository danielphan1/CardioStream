<objective>
Close motion-language gap #1 from the impeccable animate survey: GuideOverlay currently does
`if (!open) return null` -- a hard, instant mount/unmount with zero transition -- while every other
overlay-like surface in the app (LogoutConfirmDialog in Header.tsx) already intends a fade. Give both
the backdrop div and the scrollable `[role="region"]` element a <=250ms opacity fade on open AND close,
`motion-reduce:transition-none`, by keeping the component mounted briefly during the exit transition
(a local delayed-unmount mechanism) instead of the current instant `return null`.

a genuine state-machine change, not just an added transition class on an already-mounted/already-
conditionally-rendered element) -- GuideOverlay's existing focus-management, Escape-to-close, and
`inert` handling (all load-bearing for a voice-primary, no-reliable-pointer user) must come through
byte-for-byte unchanged.

breaks it, without touching any of the accessibility mechanics GuideOverlay exists to provide.

`frontend/src/components/GuideOverlay.test.tsx` (new assertions locking the new contract), live-

## Design decision: keep Escape/focus effects keyed on `open`, gate only the render on the new state

Both existing effects (Escape-to-close, focus management) stay EXACTLY as they are -- same dependency
arrays, same bodies, same position in the file. Do NOT re-key them onto the new `mounted`/`shown`
state. Reasoning: Escape-to-close's window listener attaching/detaching only while the guide is
logically open is unaffected by how long the DOM sticks around during the exit fade -- it works today
and needs no change. Focus restoration (moving focus to `#guide-toggle-button` the instant `open`
goes false) SHOULD happen immediately, not wait for the 250ms exit fade to finish -- focus has no
visual component, and App.tsx's own `inert={guideOpen}` toggling on Header (see App.tsx's
`<div inert={guideOpen} ref={headerRef}>`) is ALSO keyed directly on the store's `open`/`guideOpen`
value, not on this component's local render state -- so Header becomes interactive again on the same
frame `open` flips false regardless of what GuideOverlay's own fade is doing. Keeping both effects
keyed on `open` is therefore both lower-risk (smaller diff) and the semantically correct choice: only
the VISUAL fade is delayed, nothing about focus or `inert` timing changes.
