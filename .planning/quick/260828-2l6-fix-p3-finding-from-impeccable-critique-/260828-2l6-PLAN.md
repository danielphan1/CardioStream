<objective>
Fix the P3 finding from the 2026-08-27T20-44-31Z impeccable critique of `frontend/src/App.tsx`: BP Timeline band labels collide with the plotted lines they identify. Quick task 260827-25p already fixed label-vs-label collision (dropping the Elevated/Stage 1 labels entirely, since those two bands are too thin to hold a label at all); it did not fix label-vs-DATA collision for the remaining four bands -- observed live on the default "All data" view, where the diastolic line cuts directly through the "Hypotension" label.

Root cause (confirmed by reading `recharts/zIndex/DefaultZIndexes` in the installed Recharts 3.9 package): a `ReferenceArea`'s `label` already renders in Recharts' `label` zIndex layer (2000), which paints ABOVE the `Line` zIndex layer (400) -- so the current bare-text label is already drawn on top of the lines, not behind them. The visual "cuts through" effect happens anyway because a bare SVG `<text>` glyph has transparent gaps between and around each letter; a line drawn earlier in that same top layer's neighborhood still reads, to the eye, as passing through the word. Giving the label a solid, opaque background chip -- painted in the same top layer, behind its own text -- fully occludes any line segment underneath it, which bare text structurally cannot do regardless of z-order.

This plan replaces the four remaining bands' plain-text `bandLabel()` rendering with a `makeBandLabelChip()` custom SVG label (a solid rounded pill in the category's own clinical color, matching the `categoryColor()`/`CHIP_TEXT` pair FilterBar and StatsStrip already use for that category) -- reusing the existing category-chip pill visual language instead of inventing a new treatment, per the critique's own suggested fix and DESIGN.md's rule that `full` (pill) radius is "reserved for information-bearing chips only."

Purpose: the BP Timeline is the app's default, highest-stakes hero chart -- the first glanceable read of Chris's own BP trend -- and a label the user cannot read because a line is drawn through it defeats the point of labeling the band at all.

Output: a new `estimateChipWidth` pure sizing helper + tests in `frontend/src/lib/chartData.ts`, and an updated `BPTimeline.tsx` where the four labeled bands render a solid chip instead of bare text -- committed in one commit.
</objective>
