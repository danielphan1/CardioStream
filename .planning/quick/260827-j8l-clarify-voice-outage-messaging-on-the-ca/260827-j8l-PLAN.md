<objective>
Fix the P0 finding from the impeccable critique re-pass (2026-08-27): the CardioStream dashboard's
voice-outage messaging currently presents voice as fully live (a rotating "Try: ..." vocabulary-
teaching placeholder keeps rotating even while the agent is unavailable) while separately inviting a
doomed retry ("Try: 'show my pulse'" in the network-failure error), even though PRODUCT.md documents
the production agent as permanently unreachable ($0 API credits, a billing-only fix deferred to v2).

This plan makes three copy/rendering-branch-only changes, no state-shape changes:
1. Rewrite AGENT_UNAVAILABLE_BANNER_COPY in copy.ts to name voice AND text as the affected
   channels and to stop implying "the buttons below still work" is itself the fix for Chris (who
   cannot reliably use buttons).
2. Rewrite OFFLINE_COPY in CommandBar.tsx to drop the "Try: 'show my pulse'" doomed-retry
   invitation while keeping the actionable-error shape (what failed + the real alternative).
3. Make CommandBar.tsx reactively READ useAgentStatus's shared unavailable boolean (it currently
   only WRITES to it via reportOutcome) and branch the placeholder: a static
   "Voice and text commands aren't available" string while unavailable, the existing rotating
   example otherwise.

Purpose: stop the UI from teaching voice vocabulary and inviting retries for a channel that is
known, at the product level, to be permanently down -- while keeping the calm, word-based,
non-alarming tone DESIGN.md's Signature Component section already establishes for this exact bar.

Output: copy.ts and CommandBar.tsx updated; CommandBar.test.tsx updated (one existing assertion
fixed to match the new OFFLINE_COPY) and extended (two new tests for the unavailable/available
placeholder branch) -- committed in one commit.
</objective>
