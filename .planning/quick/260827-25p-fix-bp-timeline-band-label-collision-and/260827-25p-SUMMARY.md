# Phase quick-260827-25p Plan 01: Fix BP Timeline band-label collision and crowded mobile dots Summary

Suppressed the two AHA band labels (Elevated, Stage 1) that visually collide at hero-chart height on the BP Timeline, and added a `isDotCrowded` width-aware predicate that hides per-point dots on BPTimeline and PulseTrend when the chart is too narrow for its point count — fixing both confirmed P1 findings from the `/impeccable clarify` design-review pass, with zero changes to any locked clinical/chart-series color token.

## What Was Built

- **`isDotCrowded(width, pointCount)`** in `frontend/src/lib/chartData.ts` — a pure, framework-free predicate (`width / pointCount < 10`, with `width <= 0 || pointCount <= 1` guarded to `false`) that determines whether per-point dots would visually overlap at the chart's current rendered width.
- **`useElementWidth<T>()`** in `frontend/src/hooks/useElementWidth.ts` — a new `ResizeObserver`-backed hook returning `{ ref, width }`, observing the chart's actual rendered container width (not viewport width, which diverges inside the `max-w-[1280px]` content column).
- **`BPTimeline.tsx`**: wired `useElementWidth`/`isDotCrowded`; `dot={crowded ? false : { r: 5 }}` on both systolic and diastolic `<Line>`s; `activeDot={{ r: 10 }}` untouched; Elevated and Stage 1 `ReferenceArea` labels changed to `label={undefined}` unconditionally (the other four bands' hero-conditional labels are untouched); added rationale comment explaining the 10-unit-span/22px-tall collision and that Y-axis ticks + tooltip/chip remain the authoritative category source.
- **`PulseTrend.tsx`**: identical `useElementWidth`/`isDotCrowded` wiring on its single pulse `<Line>`; no band-label changes (this chart has no `ReferenceArea` bands).
- **`chartData.test.ts`**: 5 new tests covering `isDotCrowded`'s generous-spacing (false), the reported mobile case (true), and three degenerate-input cases (all false).
