<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Caregiver/Chris browser -> `POST /labs`, `/incidents`, `/procedures` | Bearer-token-authenticated client submits untrusted JSON bodies (free-text `notes`, `test_name`, `incident_type`, `duration`, `procedure_name`, `location`, `outcome`) that cross into the backend and are persisted to the DB |
| FastAPI route handler -> SQLAlchemy ORM -> DB | Validated Pydantic model crosses into a parameterized ORM insert (`session.add(Model(...))`) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Spoofing | labs/incidents/procedures routers (auth bypass) | mitigate | `dependencies=[Depends(verify_token)]` attached at `include_router` time in `main.py` for all 3 routers, identical to readings/stats/upload — never a per-route `Depends`. Verified by 6 gating tests added in Plan 07-02. |
| T-07-02 | Tampering | `LabResultCreate`/`IncidentCreate`/`ProcedureCreate` (mass-assignment / over-posting) | mitigate | Create schemas declare only the D-03 field list (no `id`, no server-managed column); `LabResult(**body.model_dump())`/`Procedure(**body.model_dump())` and the explicit `Incident(datetime_=body.datetime, ...)` construction can only ever set fields the Pydantic model exposes — a client cannot inject `id` or any column outside the declared schema. |
| T-07-03 | Tampering (injection) | Free-text fields (`notes`, `test_name`, `incident_type`, `duration`, `procedure_name`, `location`, `outcome`) | mitigate | All writes go through SQLAlchemy 2.0 typed declarative `session.add(Model(...))` — parameterized statements only; no raw SQL or string interpolation anywhere in the new routers. |
| T-07-04 | Denial of Service | Unbounded `Text` columns (`notes` etc.) accept arbitrarily large payloads | accept | No request-size limit on any existing data route either (readings/upload); single-user app behind the Bearer + shared-password gate; consistent with existing precedent, not a new exposure introduced by this phase. |
| T-07-05 | Information Disclosure | Pydantic 422 validation errors on malformed POST bodies | accept | FastAPI's default 422 body echoes only field names/types, no DB/internal details — identical to the existing `GET /readings` 422 behavior already accepted codebase-wide. |
</threat_model>
