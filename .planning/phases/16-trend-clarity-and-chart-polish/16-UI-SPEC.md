### Trend vs. raw visual contract (D-04, D-05 — new this phase)

| Property | Raw line (today's data, dimmed) | Trend line (7-reading rolling average, bold) |
|---|---|---|
| Color | same series token, unchanged | **same series token** — no new hue |
| Stroke width | 3px → **2px** | **4px** (new, bolder than raw ever was) |
| Stroke opacity | 1 → **0.85** | 1 (unchanged, full opacity) |
| Dash pattern (pulse only) | `9 5`, unchanged | `9 5`, unchanged (dash separates pulse from systolic under greyscale/CVD regardless of weight) |
| Dots | unchanged (`{r:5}` when not crowded, `isDotCrowded()` hides at high density) | **none** (`dot={false}`) — a computed average has no discrete "reading" to mark |
| Active dot (click target) | unchanged (`{r:10}`) — stays the real interactive affordance | **none** (`activeDot={false}`) |
| JSX z-order | render **before** the trend lines (Recharts 3 z-order is JSX order — bold trend must paint on top of dimmed raw, same file already documents this exact rule for bands-before-lines) | render **after** raw lines, **before** overlay `ReferenceLine` markers (markers stay topmost, unchanged) |
| End-of-line label pill (`makeEndLabel`) | **only** when no trend line exists for that series (< 7 total points) — existing pill, unchanged | **carries the pill when a trend line exists** (≥ 7 points) — same text/color/pill style as today, just moved from raw's last point to trend's last point |

**Contrast verification (do before merging):** at 0.85 stroke opacity, the tightest pair is light-theme diastolic-on-mist at **3.34:1** — clears the 3:1 WCAG 1.4.11 non-text floor with margin. All 12 line/background/theme combinations clear 3.3:1+ at this opacity (full computation table below); do not lower raw opacity below 0.85 without re-running this check, since the floor is reached in the low-0.78 range for that same pair.

| Theme | Line | vs deck | vs mist |
|---|---|---|---|
| Light | systolic | 6.95:1 | 6.36:1 |
| Light | diastolic | 3.67:1 | **3.34:1** (tightest) |
| Light | pulse | 4.21:1 | 3.85:1 |
| Dark | systolic | 7.33:1 | 6.74:1 |
| Dark | diastolic | 8.18:1 | 7.51:1 |
| Dark | pulse | 6.44:1 | 5.92:1 |

Extend `frontend/src/tests/contrast.test.ts` with these blended (alpha=0.85 over deck/mist) values as a new regression block, mirroring its existing `VITALS_LINES` pattern — this is the "confirm existing tokens still pass contrast at whatever opacity D-04's dimming lands on" check `16-CONTEXT.md`'s canonical_refs flagged.

### Tooltip behavior (unchanged, confirmed by code read)

`ChartTooltip.tsx` reads `payload[0].payload.reading` — the raw `Reading` object carried on every `TimePoint`, which both the raw AND trend `<Line>` elements will share (same `points` array backs both). **No tooltip copy change needed**: clicking anywhere near either a raw or trend point continues to show the exact original reading's real systolic/diastolic/pulse/notes/category — this IS the "raw data stays inspectable via the existing click-tooltip" promise from D-04, already true by construction once trend lines are added to the same data array.

## Interaction / Data Contract (rolling average)

Not a template section, but load-bearing for the planner — locked by `16-CONTEXT.md`, restated here as the researcher's confirmation these are implementable as specified:

- **D-01:** count-based window, last **7 readings** (not calendar days).
- **D-02:** no partial-window averaging — trend value undefined for the first 6 points of any series; Recharts skips `undefined`/`null` datapoints by default (no `connectNulls`), so the trend line simply starts at the 7th point with no extra config.
- **D-03:** all three series (systolic, diastolic, pulse) get a trend line whenever their raw line is shown (respects existing `showBP`/`showPulse` props — no new prop needed).
- New pure function belongs in `frontend/src/lib/chartData.ts` beside `toTimePoints`/`groupAmPm` (established pattern, per canonical_refs) — e.g. `rollingAverage(points: TimePoint[], key: "systolic"|"diastolic"|"pulse", window = 7): (number | undefined)[]`, unit-tested for: exact 7-count window, a gap in the series (readings aren't daily — `16-CONTEXT.md`'s own flagged risk), fewer than 7 total points (all-undefined), and exactly 7 points (single defined value at the last index).

## Readability Pass (D-06 — concrete findings from reading the real components)

`16-CONTEXT.md` left D-06 open ("no specific pain point named this round"). These are the two concrete, code-grounded issues found by reading `CategoryBars.tsx` and `AmPmComparison.tsx` directly — not invented busywork. `CombinedTimeline.tsx`'s own density complaint is already addressed for free by the raw-line dimming above (per `16-CONTEXT.md`'s own prediction), so no further change is specified there beyond the trend-line work.

### CategoryBars.tsx — fixed 300px right margin squeezes bars on narrow viewports
`margin={{ top: 8, right: 300, bottom: 8, left: 8 }}` is a fixed value regardless of container width. On a ~343px mobile content column (375px viewport − 16px gutters ×2), 300px of reserved label space leaves ~35–43px for the actual bar plot — the bars become unreadable slivers. No responsive handling exists today (confirmed: no `useElementWidth` import, no breakpoint classes in this file).

**Contract:** reuse `useElementWidth` (already imported by `CombinedTimeline.tsx` — established pattern, don't invent a second width-detection approach). Below a 480px container width: right margin → **160px**, D-10 label font → **16px** (down from 18px — this specific text sits in the chart-annotation exception band alongside the existing 14–16px chip/axis text, not the body-copy 18px floor, since it's a per-bar data label, not running prose). Do **not** truncate the label text — full "Stage 1 — 34 readings (26%)" string must still render (DESIGN.md's No-Off-Screen Rule spirit: shrink, don't clip or truncate). Verify live at 375px width before merging.

### AmPmComparison.tsx — fixed `gap-8` (32px) between two side-by-side panels on narrow viewports
`<div className="flex h-full w-full gap-8">` always renders two full `BarChart` panels side-by-side, each with its own axis, tick labels, and per-bar AM/PM+value text labels, inside the parent's fixed `h-[420px]`. No responsive stacking exists today.

**Contract, scoped deliberately narrow:** reduce `gap-8` → `gap-4` below a 480px container width (reclaims 16px for the bars themselves) using the same `useElementWidth` pattern as above. **Do not** attempt vertical stacking (flex-col) as the fix — that would need a taller container than `ChartDeck.tsx`'s blanket `h-[420px]` (line 161, `className={fixedHeight ? "h-[420px]" : undefined}`) provides for every non-timeline view, and `ChartDeck.tsx` is outside this phase's canonical file list (`16-CONTEXT.md` names `CombinedTimeline.tsx`, `CategoryBars.tsx`, `AmPmComparison.tsx` only). If the gap-only fix still reads as cramped at 375px during live verification, escalate the `ChartDeck.tsx` fixed-height coupling to the planner as a follow-up rather than silently expanding this phase's file scope.
