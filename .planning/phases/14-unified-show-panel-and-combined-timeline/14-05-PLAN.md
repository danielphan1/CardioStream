<objective>
Build `CombinedTimeline` — one chart carrying systolic, diastolic, and pulse on two independent
axes, with event markers over the top.

Purpose: `bp_timeline` and `pulse_trend` being mutually exclusive is the direct cause of "only see
the blood pressures and pulses" being impossible. This chart is the phase's payload.
Output: one new chart component; `BPTimeline` and `PulseTrend` deleted after their machinery moves.
</objective>

  <read_first>
    - frontend/src/components/charts/BPTimeline.tsx (band ReferenceArea pairs, `makeBandLabelChip`, `makeEndLabel`, tooltip/dismiss wiring, marker loop)
    - frontend/src/components/charts/PulseTrend.tsx (pulse domain, ticks, bradycardia ReferenceLine)
    - frontend/src/lib/chartData.ts (`toTimePoints`, `isDotCrowded`, `prefersReducedMotion`)
    - .planning/phases/14-unified-show-panel-and-combined-timeline/14-UI-SPEC.md (§4)
  </read_first>
  <action>
    Create `charts/CombinedTimeline.tsx` with props
    `{ readings, overlayEvents, showBP, showPulse }`. No `variant` prop — the mini-card rotation is
    gone, this is always the hero.

    Axes — **both always mounted**, visibility via `hide`:
    - `<YAxis yAxisId="mmHg" domain={[40,220]} ticks={[40,90,120,130,140,180,220]} hide={!showBP} />`
    - `<YAxis yAxisId="bpm" orientation="right" domain={[30,120]} ticks={[30,60,90,120]} hide={!showPulse} />`

    Keeping both mounted is load-bearing, not defensive: Recharts resolves `yAxisId` against mounted
    axes, so unmounting `mmHg` while an event `ReferenceLine` still points at it drops the marker
    with no error. Verified against recharts 3.9.2 types — `yAxisId` exists on `YAxis`, `Line`,
    `ReferenceLine`, and `ReferenceArea`, defaulting to `0`.

    Series (each tagged with its axis):
    - systolic + diastolic, `yAxisId="mmHg"`, solid width 3 — rendered only when `showBP`
    - pulse, `yAxisId="bpm"`, `strokeDasharray="9 5"`, `stroke="var(--line-pulse)"` — only when `showPulse`

    Conditional chrome:
    - AHA bands only when `showBP`, all `yAxisId="mmHg"`. **Port the two-ReferenceArea split verbatim**
      — background tint at default zIndex plus an invisible label-host at
      `zIndex={DefaultZIndexes.axis}` carrying the chip. That split was the fix for a real z-order
      bug (`260828-4nj`); collapsing it back to one element reintroduces lines painting over chips.
      Elevated and Stage 1 stay chip-less for the same reason as before (bands too thin).
    - 60 bpm bradycardia `ReferenceLine` `yAxisId="bpm"` only when `showPulse`
    - Event markers: vertical `ReferenceLine` per event, `yAxisId="mmHg"` unconditionally, glyph and
      colour from `OVERLAY_META`, `ifOverflow="extendDomain"`
    - Line-end labels via `makeEndLabel` for whichever vitals are on

    Keep the click-persistent tooltip and the ArrowLeft/ArrowRight `dismissed` reset from
    `BPTimeline`, and `accessibilityLayer` on.
  </action>
  <acceptance_criteria>
    - Both `YAxis` elements are present in the rendered tree with `showBP: false, showPulse: true`
    - With `showBP: false`, no systolic/diastolic `Line` and no band `ReferenceArea` renders
    - With `showPulse: false`, no pulse `Line` and no bradycardia `ReferenceLine` renders
    - The pulse `Line` carries `strokeDasharray` and `var(--line-pulse)`
    - Band label chips still render as a tint + label-host ReferenceArea pair with an explicit zIndex
    - `npx tsc -b --noEmit` clean for this file
