# Phase 5 — UI Design Contract

> Visual and interaction contract for the two NEW caregiver surfaces this phase introduces (a full-screen login gate and a caregiver upload page) plus the discreet header admin controls. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This phase does NOT invent a design system.** It inherits the nautical two-theme token system locked in `02-UI-SPEC.md` (approved 2026-07-14) — same tokens, same spacing scale, same typography, same font, same icon library, same friendly non-technical copy voice. Only the tables that ADD or DIVERGE from Phase 2 are spelled out below; everything else is "inherit Phase 2 verbatim."
>
> Theme in one sentence (inherited): **a calm coastal instrument panel — pastel ocean canvas, navy ink, clinical severity colors where health meaning lives, a hint of sail in the chrome.**

---

## Accessibility Scope (read first — the deliberate split)

The project-wide accessibility non-negotiables (CLAUDE.md) exist for **Chris's daily voice dashboard**. This phase deliberately scopes them per surface (CONTEXT.md D-04, D-07). The planner must NOT over-apply the voice/48px rules to the caregiver screens, nor under-apply the readability rules.

| Surface | Voice-operable (ACC-03) | ≥48px targets / no precision pointing | ≥18px readable + high contrast | Keyboard operable + visible focus |
|---------|-------------------------|----------------------------------------|--------------------------------|-----------------------------------|
| **Chris's dashboard** (existing, unchanged) | REQUIRED | REQUIRED | REQUIRED | REQUIRED |
| **LoginGate** (D-01, D-04) | **EXEMPT** — caregiver keyboard-entry ritual; the secret never travels the voice path. A normal password `<input>` is correct. | **EXEMPT** (still made generous — see below) | **REQUIRED** | **REQUIRED** |
| **UploadPage** (D-05, D-07) | **EXEMPT** — occasional caregiver admin, never operated by Chris. Standard OS file-picker button allowed. | **EXEMPT** (still large & high-contrast) | **REQUIRED** | **REQUIRED** |
| **Header admin controls** (D-06) | EXEMPT (caregiver affordances) | Kept small/discreet on purpose (D-06) — exempt from the 48px floor so they stay out of the way of Chris's large voice/chart UI | REQUIRED | REQUIRED |

Practical consequence for the executor: LoginGate and UploadPage MUST still be large, high-contrast, ≥18px, fully keyboard-operable with the inherited 3px focus ring — they are exempt only from the voice-operable / mandatory-48px / no-precision-pointing rules. The native `<input type="file">` OS button is explicitly allowed (D-07) and is exempt from the 48px floor since the browser sizes it.

## Spacing Scale

Inherits the Phase 2 8-point scale verbatim (all multiples of 4): `xs 4 · sm 8 · md 16 · lg 24 · xl 32 · 2xl 48 · 3xl 64`. Usage additions for this phase's surfaces:

| Token | Value | Phase 5 usage |
|-------|-------|---------------|
| md | 16px | Gap between login card label → input → button; upload page control gaps; header control gaps |
| lg | 24px | Login card inner padding; upload page section padding; gap between summary sentences and the reject disclosure |
| xl | 32px | LoginGate card padding on ≥768px; vertical rhythm between upload page sections (heading → instructions → picker → result) |
| 2xl | 48px | Login "Enter" button height and "Choose a file" button min-height (kept ≥48px even though exempt — costs nothing, aids the caregiver); logout-confirm dialog buttons |

Exceptions (documented):
- **Native `<input type="file">` OS button** — browser-sized, exempt from the 48px floor (D-07). The styled `<label>` wrapping it IS sized to ≥48px so the visible affordance stays large.
- **Header "Upload" / "Log out" controls** — intentionally discreet (D-06), sized to fit compactly in the header corner; exempt from the 48px floor per the Accessibility Scope table.

## Color

Inherits the full Phase 2 light + dark palette (all tokens already defined in `frontend/src/index.css`). No new color tokens are introduced. The clinical-severity reds remain reserved for BP categories (D-14) and MUST NOT be reused for auth/upload messaging.

| Role | Light | Dark | Phase 5 usage |
|------|-------|------|---------------|
| Dominant (60%) | `#F2F7F5` foam | `#0B1626` navy-black | LoginGate full-screen background; upload page background |
| Secondary (30%) | `#E2EDF2` sky | `#13233A` deep sea | LoginGate card surface; upload page panels; result-summary panel; reject-details panel; logout-confirm dialog surface |
| Ink (text/border) | `#14213D` navy | `#E8F1EF` pale foam | All text, icons, input borders, card borders |
| Accent (10%) fill | `#14213D` navy (white text) | `#8FC1D4` sky (`#0B1626` text) | See reserved list below |
| Focus ring | `#1D4E89` | `#8FC1D4` | 3px `focus-visible` ring + 2px offset on every interactive element (inherited `:focus-visible` rule) |
| Destructive | none (no clinical-red reuse) | none | This phase has no data-destroying action; Log out is reversible (re-login) — see notice/confirm treatment below |

**Accent (filled) reserved for exactly (Phase 5 additions to the Phase 2 list):** the login **"Enter"** button, the upload **"Choose a file"** styled label-button, and the **"Log out"** confirm button inside the logout dialog. Nothing else gets an accent fill. Specifically NOT accent-filled: the discreet header "Upload" and "Log out" controls (D-06 — kept subtle: sky surface, 2px navy border, navy text, OR a plain underlined text link), the reject-details disclosure toggle, and the dialog "Cancel" button (bordered sky).

**Error / notice treatment (no new color):** wrong-password, non-OMRON rejection, and generic upload-failure messages render as **Body 18px in `--color-ink` (bold 700 for the first sentence)** inside a `--color-sky` panel bordered 2px `--color-ink`, preceded by a `TriangleAlert` icon (`aria-hidden="true"`). Calm, non-alarming, no red — consistent with the project's no-alarm-language discipline and keeping the clinical reds unambiguous. Success uses a `CheckCircle2` icon in `--color-ink` on the same sky panel.

## Copywriting Contract

Voice: calm, first-person-neutral, sentence case, no exclamation marks, no technical terms, no status codes or tracebacks ever (D-10). Dates written "June 13, 2025" (inherited Phase 2 convention; the user's "June 13" shorthand in D-09 was illustrative).

### Login gate (D-01, D-04, SEC-01)

| Element | Copy |
|---------|------|
| Brand | "Chris's Health Dashboard" (Display 32, with `Sailboat` mark `aria-hidden="true"`) |
| Sub-heading | "Enter the password to continue" (Heading 24) |
| Field label | "Password" (Label 20, `<label for>` a native `<input type="password">`) |
| Primary CTA | **"Enter"** (accent fill; disabled until the field is non-empty) |
| Wrong-password error | "That password didn't work. Please try again." (notice treatment; the field stays populated-cleared per implementation, focus returns to the input) |
| Signed-out notice (arriving via a 401 → auto-logout from elsewhere, D-03) | "You've been signed out. Enter the password to continue." (shown in place of the sub-heading when returning involuntarily) |

### Upload page (DASH-10, D-08, D-09, D-10)

| Element | Copy |
|---------|------|
| Page heading | "Add new readings" (Heading 24) |
| Instructions | "Choose the .xlsx file you exported from the OMRON app. New readings are added automatically — uploading the same file twice is safe." (Body 18) |
| Primary CTA (file picker) | **"Choose a file"** (styled `<label>` wrapping a visually-hidden `<input type="file" accept=".xlsx">`; selecting a file ingests immediately — no preview/confirm step, D-08) |
| Selected-file line | "Selected: {filename}" (Body 18, shown after pick) |
| Loading state | "Reading your file…" (Body 18, with `aria-busy="true"`; replaces the file line while the POST is in flight) |
| Success summary (D-09) | Assembled from the locked `IngestSummary` as plain sentences (see assembly rules below) — e.g. "Added 12 new readings. 3 were already on file. 0 skipped. Your data now goes through June 13, 2025." |
| Rejected-rows summary | Folded into the summary's "{n} skipped." sentence; when n > 0 a disclosure appears (D-10) |
| Reject disclosure toggle | "Show which rows" (collapsed default) / "Hide details" (expanded) — `ChevronDown` rotates; `aria-expanded` wired |
| Rejected-row line (each) | "Row {row_index}: {reason}." — `row_index` and `reason` are the two fields of the ETL's value-free `RejectedRow` (backend/app/etl.py); `reason` comes verbatim (e.g. "missing systolic value", "the date could not be read") — never echoes a health value |
| Non-OMRON / unparseable file (D-10) | "This doesn't look like an OMRON export. Nothing was added. Please choose the .xlsx file you exported from your OMRON app." (notice treatment; no summary rendered — the file ingested nothing) |
| Generic upload failure (network / mapped non-401 error) | "Something went wrong reading that file. Nothing was added — please try again." (notice treatment; never a raw traceback or status code) |
| Return-to-dashboard affordance | "Back to dashboard" (header view-toggle, see Layout) |

**Result-sentence assembly rules (D-09, from `IngestSummary` fields added / updated / unchanged / rejected / total / latest):**
1. `Added {added} new reading{s}.` — always shown (pluralize: 1 → "reading", else "readings").
2. `Updated {updated} reading{s} that changed.` — shown **only when `updated` > 0** (keeps the common case matching the user-endorsed verbatim exactly).
3. `{unchanged} {was|were} already on file.` — always shown ("1 was", else "were"); shows zero for reassurance.
4. `{rejected} skipped.` — always shown (matches the endorsed "0 skipped.").
5. `Your data now goes through {latest as "Month D, YYYY"}.` — shown when `total` > 0.

### Header admin controls (D-06)

| Element | Copy |
|---------|------|
| View toggle (on dashboard) | "Upload" (with `Upload` icon; navigates to the upload view) |
| View toggle (on upload view) | "Back to dashboard" (navigates back) |
| Log out control | "Log out" (with `LogOut` icon) |

### Destructive / high-cost confirmation

| Action | Confirmation copy |
|--------|-------------------|
| **Log out** (D-03) | Dialog — Title: "Log out?" (Heading 24) · Body: "You'll need the password to unlock the dashboard again." (Body 18) · Buttons: "Cancel" (bordered sky) and **"Log out"** (accent fill). **Rationale (justifies the confirm step):** the token has no expiry and Chris cannot re-enter the password himself (D-02) — an accidental logout ends his hands-free session and requires a caregiver to return. A single lightweight confirm is warranted even though logout destroys no data. |

Upload itself needs **no** confirmation (D-08 immediate idempotent ingest — re-uploading the same file is a visible no-op, so there is nothing to undo).

## Layout & Interaction Contract

**Routing (D-05):** a zustand view-state swap between `"dashboard"` and `"upload"` (05-RESEARCH.md Pattern 4) — no URL change, no react-router, no Vercel rewrite. The **LoginGate wraps everything**: until a token is present in the auth store, ONLY the LoginGate renders — no header, no dashboard chrome, no data fetch fires (D-01, no blur-overlay, no pre-auth data leak).

1. **LoginGate** (pre-auth, full-screen): foam background filling the viewport; a single sky card, centered vertically and horizontally, `max-width: 28rem` (448px), padding `lg`→`xl`, 2px ink border, subtle rounded corners. Contents top-to-bottom: `Sailboat` mark + "Chris's Health Dashboard" (Display), sub-heading, "Password" label + `<input type="password">` (full-width, ≥48px tall, 2px ink border, autofocus), "Enter" accent button (full-width). Wrong-password notice appears below the input. Submitting on Enter key === clicking "Enter". Optional decorative wave divider under the brand (inherited `Header` SVG motif) — `aria-hidden`, no imagery behind the field.

2. **Header** (post-auth, persists across both views): inherits the existing `Header.tsx` (Sailboat + Display title + theme toggle). ADD a right-corner caregiver-controls zone (D-06): the view toggle ("Upload" / "Back to dashboard") and "Log out", both discreet — sky surface with 2px ink border and navy text (or a plain underlined text link), Label 20, kept small so Chris's chart/voice UI stays visually dominant. Never accent-filled.

3. **Dashboard view** — unchanged from Phases 2–4.

4. **UploadPage view** (post-auth, caregiver-only): single-column, generous gutters, on foam. Order: page heading → instructions → "Choose a file" styled label-button + selected-file line → (on submit) loading line → result panel. The **result panel** (sky, bordered) renders either: the `CheckCircle2` + plain-language summary sentences (D-09) with the reject disclosure when `rejected` > 0, OR the `TriangleAlert` + non-OMRON / generic-failure notice. No numeric stat-tiles anywhere (D-09).

5. **Logout confirm dialog**: a small centered modal on a dimmed backdrop, sky surface, 2px ink border; title + body + [Cancel] [Log out]; Escape and backdrop-click both cancel; focus is trapped and returns to the "Log out" control on close. Confirming clears the token from the auth store and localStorage and returns to the LoginGate (D-03).

**Focus & keyboard:** every control shows the inherited 3px focus ring; LoginGate autofocuses the password input; the file picker is reachable by keyboard (the visually-hidden native input is focus-linked to its styled label); the dialog traps focus. No hover-only information; no drag; no precision pointing required on any of these surfaces.

**Motion:** reuse the inherited motion discipline — any dialog/notice transition is a ≤250ms opacity fade, `motion-reduce:transition-none` for instant under `prefers-reduced-motion`.

**Responsive:** single column throughout; page gutter 16px (<768px), 32px (768–1279px), 64px (≥1280px) — inherited. The LoginGate card stays centered and `max-width`-capped at every breakpoint.
