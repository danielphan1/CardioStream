<objective>
Build the frontend auth gate. A localStorage-guarded zustand `auth` store (mirroring `theme.ts`) holds the Bearer token; `client.ts` attaches `Authorization: Bearer <token>` on every request, adds a `postFile` multipart helper and a `postAuth` wrapper, and clears the token on any 401; a full-screen nautical `LoginGate` (password input + "Enter") wraps `App` so nothing renders — and no data fetch fires — until a token exists (D-01). Login is a caregiver keyboard ritual, NOT voice-operable (D-04); the token does not auto-expire (D-02).

Purpose: SEC-01 frontend half — the shared-password gate and Bearer attachment.
Output: `store/auth.ts`, extended `client.ts`, `LoginGate.tsx`, gate-wrapped `App.tsx`, and their tests.
</objective>

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-05-11 | Spoofing | stale/forged token in localStorage | mitigate | Any 401 from the backend triggers `useAuth.logout()` in client.ts, returning to the gate; the backend signature check (Plan 02) is the real boundary. Verified by the 401→logout client test. |
| T-05-12 | Information Disclosure | secret traveling the voice path | accept→mitigate | Login is keyboard-only, exempt from ACC-03 by design (D-04); a normal password `<input>` keeps the secret off the voice path. |
