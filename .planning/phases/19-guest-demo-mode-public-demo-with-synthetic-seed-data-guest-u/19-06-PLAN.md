<objective>
Implement the two visible surfaces of demo mode: `LoginGate`'s conditional guest-username field, and
`Header`'s persistent demo badge plus hidden write-oriented buttons.

Purpose: `LoginGate` and `Header` are architecturally different beasts here even though both read the
SAME `demoMode` boolean. `LoginGate` renders standalone in 5 existing unit tests with no
`QueryClientProvider` ancestor (19-RESEARCH.md Pitfall 4), so it detects `demoMode` via a plain
`useEffect` + the raw `getHealth()` client function — NOT the `useHealth()` TanStack Query hook (a
deliberate deviation from `19-UI-SPEC.md`'s literal suggestion, smaller test blast radius, same
single-source-of-truth outcome). `Header` is always mounted deep inside the authed,
`QueryClientProvider`-wrapped tree, so it safely reuses the EXISTING `useHealth()` hook (already
polling `/health` every 60s for `AgentStatusBanner`) with zero new fetch call. Both surfaces implement
`19-UI-SPEC.md`'s locked Component Contract verbatim.
Output: `LoginGate.tsx` + extended `LoginGate.test.tsx`; `Header.tsx` + new `Header.test.tsx`.
</objective>
