<objective>
Add the backend half of the new `toggle_speech` voice/text command (D-01): a seventh
closed-union member on the Claude-facing `AgentOutput.result` schema, the matching
`AppliedFilters.speechEnabled` field, the `interpret()` dispatch branch that maps it to a
server-composed reply, and the `SYSTEM_PROMPT` vocabulary that teaches the model the command
shape. `ToggleSpeech` is a byte-for-byte structural mirror of the existing `ToggleDataset`
(Phase 9) minus its `dataset` discriminator — explicit on/off only, never a flip/toggle, and
never a client-side keyword shortcut that bypasses `/agent` (D-01 explicitly forbids this — the
server stays the sole authority on command intent, per `lib/voice.ts`'s documented trust
boundary).

Purpose: TTS-02 requires the mute/quiet toggle be "voice-reachable." This plan delivers the
voice/text half (the click half is Plan 10-05's `Header.tsx` button). Pure, mechanical
extension of five already-proven closed-union touch-points in this file set (RESEARCH: HIGH
confidence) — no new architecture, no new library, no new route.
Output: `ToggleSpeech` round-trips through `AgentOutput`, `interpret()` maps it to
`AppliedFilters(speechEnabled=...)`, and the system prompt routes mute/unmute utterances to it.
</objective>
