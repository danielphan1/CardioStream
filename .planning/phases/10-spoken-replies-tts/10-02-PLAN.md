  <behavior>
    - `useSpeech.getState().enabled` defaults to `true` (TTS-02 — on by default), even with no prior localStorage write.
    - `initSpeech()` reads `localStorage["hv-speech"]`: `"off"` → `enabled: false`; missing/anything else → `enabled: true`.
    - `setEnabled(false)` writes `"off"` to `localStorage["hv-speech"]`; `setEnabled(true)` writes `"on"`. Both guarded in try/catch — a throwing localStorage never blocks the call.
    - `toggleEnabled()` flips the current `enabled` value via `setEnabled`.
    - `speak(text)`: no-ops when `enabled` is `false` or `text.trim() === ""`; otherwise calls `speechSynthesis.cancel()` unconditionally BEFORE constructing a new `SpeechSynthesisUtterance(text)`, then calls `speechSynthesis.speak(utter)`. `isSpeaking` flips `true` on the utterance's `onstart` and `false` on `onend` OR `onerror` (Safari may fire error instead of end after cancel — Pitfall 2).
    - A monotonic `seq` counter (module-level `let`, not store state — no test needs to reset it) is incremented on every `speak()` call; `onstart`/`onend`/`onerror` handlers each compare their captured `mySeq` against the current `seq` and no-op if stale, so a late event from a CANCELLED utterance can never flip `isSpeaking` after a newer utterance has already started.
    - `primeSpeech()` calls `speechSynthesis.speak(new SpeechSynthesisUtterance(" "))` exactly once ever, gated by a `primed` flag; every call after the first is a no-op.
    - `cancelForBackground()` calls `speechSynthesis.cancel()`, forces `isSpeaking: false` synchronously (does not wait for onend/onerror), and bumps `seq` so any late event from the just-cancelled utterance is superseded.
    - `setEnabled(false)` also calls `cancelForBackground()` internally so muting mid-utterance silences immediately (RESEARCH Assumption A2).
  </behavior>

| `localStorage["hv-speech"]` | Client-only storage, readable/writable by any script on the same origin — identical risk profile to the existing `theme.ts` persistence, already accepted |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-04 | Information Disclosure | `speech.ts` `speak()`'s `text` parameter | mitigate | `speak()` never `console.log`s or otherwise persists the spoken text anywhere — it only reaches the browser's native `SpeechSynthesisUtterance` constructor, mirroring the existing SEC-03/T-04-04 "transcript never logged" project invariant. |
| T-10-05 | Tampering | `localStorage["hv-speech"]` | accept | A user with local script access could set an arbitrary value; `readStoredEnabled()` only trusts the literal string `"off"` (anything else, including garbage, defaults to the safe `true`/on) — identical accepted risk profile to `theme.ts`'s existing `hv-theme` key, a single-user personal app with no security-relevant consequence from a spoofed UI preference. |

No network calls, no new dependency, no new attack surface beyond the browser's own
`speechSynthesis` API (already covered by the platform's own user-gesture gating, RESEARCH
