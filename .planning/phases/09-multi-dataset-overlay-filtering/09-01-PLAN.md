<objective>
Add the backend half of the new `toggle_dataset` voice/text command: a sixth closed-union
member on the Claude-facing `AgentOutput.result` schema, the two matching `AppliedFilters`
fields, the `interpret()` dispatch branch that maps it to a server-composed reply, and the
`SYSTEM_PROMPT` vocabulary that teaches the model the command shape (D-03: one dataset per
command, single-valued `Literal`; D-04: explicit on/off, never a flip/toggle).

Purpose: OVERLAY-03 requires overlay toggling "by voice or click" — this plan delivers the
voice/text half (the click half is Plan 09-04's `OverlayToggle.tsx`). Pure, mechanical
extension of five already-proven closed-union patterns in this file set (RESEARCH: HIGH
confidence) — no new architecture, no new library.
Output: `ToggleDataset` round-trips through `AgentOutput`, `interpret()` maps it to
`AppliedFilters(overlayDataset, overlayState)`, and the system prompt routes toggle utterances
to it.
</objective>

|----------|--------------|
| Claude model output → AppliedFilters | Model-authored `dataset`/`state` values (untrusted per CLAUDE.md: "never execute raw model output") cross into the server-composed `AppliedFilters` reply the frontend store applies |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Tampering | `ToggleDataset.dataset`/`.state` | mitigate | Both fields are closed `Literal["labs","incidents","procedures"]`/`Literal["on","off"]` enums validated by Pydantic constrained sampling at parse time (V5) — Claude structurally cannot emit a value outside this vocabulary, matching the existing 5-variant discipline. |
| T-09-02 | Information Disclosure | `AppliedFilters.overlayDataset/overlayState` | accept | Both new fields are enums, not free text — no new leakage surface; mirrors the existing `Unintelligible`/`MedicalRefusal` disposition. |
| T-09-03 | Tampering (prompt injection) | `prompt.py` SYSTEM_PROMPT | accept | `SYSTEM_PROMPT` remains a static module constant never interpolated with user or database content — existing project invariant, unchanged by this plan. |

No new backend routes and no new auth surface this plan — V2/V3/V4 unaffected (existing Bearer
gate untouched).
