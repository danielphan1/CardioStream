# Phase 9 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase adds two new visible surfaces to the dashboard — a 3-item overlay
toggle row (Labs / Incidents / Procedures, click **and** voice, per
OVERLAY-03) and an accessible events table (OVERLAY-06) — plus new marker
rendering inside two existing chart components (BPTimeline, PulseTrend) and
a new "doesn't apply here" indicator inside two others (CategoryBars,
AmPmComparison). It does **not** introduce a new visual language: the
project has a locked, comprehensively documented design system
(`frontend/src/index.css`, header comment: "Design-token system —
02-UI-SPEC.md locked palette"). No shadcn gate was raised, for the same
reason Phases 6 and 8 skipped it — `components.json` does not exist, the
stack is React/Vite (which would normally trigger the gate), but this is a
continuation phase on an already-shipped, deliberately hand-rolled Tailwind
system, not a greenfield init. Introducing shadcn now would fork the visual
language mid-project for one toggle row and one table.

This document resolves every item `09-CONTEXT.md` left to "Claude's
Discretion" (exact icon/glyph choice per D-05, the "doesn't apply here"
visual treatment for OVERLAY-05, the toggle row's component boundary, and
copy for every new string this phase introduces) so the executor has zero
visual ambiguity left to invent at implementation time. All 8 locked
decisions (D-01–D-08) and every Architecture Pattern in `09-RESEARCH.md` are
treated as given — this spec only adds the visual/copy layer on top.

**Accent reserved-for list is unchanged by this phase** (still: Send button,
active/pressed date/AM-PM/category filter chips, CommandBar's listening
ring, Log-out confirm button, and Phase 8's active type-switcher
segment/enabled Submit button). The overlay toggle buttons are deliberately

naturally to the toggle button itself, reinforcing — not replacing — the
`aria-pressed` + word-label contract).

### New tokens this phase adds to `index.css` (light / dark pairs)

Three new marker/toggle colors, one per overlay dataset. Chosen to sit in
hue ranges **not already used** by any existing token (systolic navy ~215°,
diastolic teal ~190°, bradycardia/hypotension blue-gray ~205°, normal green
~155°, elevated gold ~45°, stage1 orange ~25°, stage2/crisis red ~0–5°) so
all three read as clearly distinct from every existing clinical/chart color
as well as from each other, at matched lightness to the existing `--cat-*`/
`--line-*` pairs (dark+saturated in light mode, light+pastel in dark mode).

| Token | Light | Dark | Dataset | Hue family |
|-------|-------|------|---------|------------|
| `--overlay-labs` | `#6A3FA0` | `#C9A6EA` | Labs | Violet (~280°) |
| `--overlay-incidents` | `#A32672` | `#F0A8D0` | Incidents | Magenta/berry (~330°) |
| `--overlay-procedures` | `#5C6B1E` | `#C9D48A` | Procedures | Olive (~75°) |

**Explicit prohibition (inherited, restated per Phase 6/8 precedent):** no
`--cat-*` clinical BP-severity token is used anywhere in this phase's
markers, toggle buttons, or table chips. Reusing e.g. `--cat-stage2` (red)
for "incidents" would visually conflate a logged fall/hospitalization with
a hypertensive-crisis blood-pressure reading — exactly the kind of
false clinical signal PROJECT.md's "no implied cross-dataset correlation"
constraint and Phase 6's "never conflate an outage with a health emergency"
precedent both guard against. The three new tokens above are the ONLY
colors this phase's new surfaces may use for type identity.

**Where each token is used (all three surfaces, same color, per type —
D-05's "shape AND color" contract, reinforced three times over):**
1. Toggle button's pressed-state fill (see Phase-Specific Component
   Contract)
2. `ReferenceLine` stroke + label fill on the hero chart
3. Type badge/chip fill in the accessible events table

**Primary focal point:** none new — this phase adds no single dominant CTA;
its "primary interactive element" is the 3-button toggle group as a whole
(see Copywriting Contract, Primary CTA row).

## Marker & Icon Contract (D-05, resolves Claude's Discretion)

Each of the 3 overlay dataset types gets one fixed icon (used on the toggle
button and in the accessible table's type badge) and one fixed geometric
glyph character (used as the `ReferenceLine` label on the chart, per
`09-RESEARCH.md` Pattern 4/Pitfall 3 — plain object `label` form, never a
nested `<Label content={...}>`). The glyph shapes are the classic
accessible-scatter-plot vocabulary (diamond/triangle/square) so type is
distinguishable by shape alone, independent of color, satisfying D-05 even
for a colorblind user reading the chart at a glance.

| Dataset | Toggle/table icon (`lucide-react`) | Chart glyph | Color token | Button label | Table type label |
|---------|-------------------------------------|-------------|-------------|---------------|-------------------|
| Labs | `FlaskConical` | `◆` (diamond) | `--overlay-labs` | "Labs" | "Lab" |
| Incidents | `AlertTriangle` | `▲` (triangle) | `--overlay-incidents` | "Incidents" | "Incident" |
| Procedures | `ClipboardList` | `■` (square) | `--overlay-procedures` | "Procedures" | "Procedure" |

**Chart marker rendering — primary path + fallback (resolves RESEARCH Open
Question 2):** attempt the icon via `label` as a direct function returning a
small inline `lucide-react` SVG (16px, `stroke={color}`, positioned `top`)
as the PRIMARY visual target. If that does not render correctly in this
Recharts version (per the flagged, unconfirmed behavior in
`09-RESEARCH.md`), fall back to the plain-object `label` form with the
glyph **character** (from the table above) as `value`, 14px, `fill: color`
— matching `BPTimeline.tsx`'s existing band-edge-label precedent exactly
(same size, same "ambient annotation" exemption). Either path satisfies
D-05; the fallback is not a degraded visual, it is a pre-approved equal
alternative — the executor does not need to escalate a design question if
the icon path fails, just use the fallback glyph verbatim.

**`ReferenceLine` stroke:** `strokeWidth={2}`, full chart height, in the
matching color token — same visual weight as `PulseTrend.tsx`'s existing
bradycardia `ReferenceLine`, but solid (not dashed) so overlay events read
as distinct from the dashed clinical-threshold line already on that chart.

## Phase-Specific Component Contract

### `OverlayToggle.tsx` (new component, sibling of `FilterBar` — not nested inside it)

Resolves the "FilterBar vs. adjacent group" discretion item: **new,
separate component**, mounted as its own peer section directly below
`FilterBar` in `App.tsx`'s `main`:

```tsx
<main className="mx-auto flex max-w-[1280px] flex-col gap-8 px-4 py-8 md:px-8 xl:px-16">
  <FilterBar latestReading={latestReading} />
  <OverlayToggle />
  <StatsStrip stats={stats.data} isLoading={stats.isPending} />
  {chartRegion}
  <section aria-label="Readings table">…</section>
  {overlayEventsSection /* see OverlayEventsList below — conditional */}
</main>
```

Rationale: `FilterBar.tsx`'s own header comment scopes it to "the exact
interactive surface Phase 3 voice commands will mirror" for
single-select filters; this is the codebase's first true multi-select
group, so it gets its own file/component boundary — the same reasoning
Phase 6 used to keep `AgentStatusBanner` a sibling of `CommandBar` rather
than a branch inside it.

**Markup/styling (exact):**

```tsx
import { AlertTriangle, ClipboardList, FlaskConical } from "lucide-react";

import { useFilters, type OverlayDataset } from "../store/filters";

const OVERLAY_META: Record<
  OverlayDataset,
  { label: string; Icon: typeof FlaskConical; color: string }
> = {
  labs: { label: "Labs", Icon: FlaskConical, color: "var(--overlay-labs)" },
  incidents: { label: "Incidents", Icon: AlertTriangle, color: "var(--overlay-incidents)" },
  procedures: { label: "Procedures", Icon: ClipboardList, color: "var(--overlay-procedures)" },
};
const OVERLAY_ORDER: OverlayDataset[] = ["labs", "incidents", "procedures"];

// pressed = filled with the dataset's own color token, not --color-accent
const inactiveClass =
  "min-h-12 flex items-center gap-2 rounded-lg px-4 text-[20px] font-bold bg-[var(--color-sky)] text-[var(--color-ink)] border-2 border-[var(--color-ink)]";
const activeClass = (color: string) =>
  `min-h-12 flex items-center gap-2 rounded-lg px-4 text-[20px] font-bold text-white border-2`; // + style backgroundColor/borderColor: color

<section className="bg-[var(--color-sky)] p-4">
  <div className="flex flex-wrap items-center gap-4">
    <span className="text-[20px] font-bold text-[var(--color-ink)]">Overlay:</span>
    <div role="group" aria-label="Overlay events" className="flex flex-wrap gap-2">
      {OVERLAY_ORDER.map((key) => {
        const { label, Icon, color } = OVERLAY_META[key];
        const on = overlayDatasets[key];
        return (
          <button
            key={key}
            type="button"
            aria-pressed={on}
            onClick={() => setOverlayDataset(key, !on)}
            className={on ? activeClass(color) : inactiveClass}
            style={on ? { backgroundColor: color, borderColor: color } : undefined}
          >
            <Icon aria-hidden="true" size={20} />
            {label}
          </button>
        );
      })}
    </div>
  </div>
  {/* "doesn't apply here" note — see below, renders in the same section
      when activeChart is bp_categories or am_pm_comparison */}
  <p aria-live="polite" className="mt-4 text-[18px] text-[var(--color-ink)]">
    {overlaySentence /* "Labs, Incidents overlaid" | "No overlays selected" */}
  </p>
</section>
```

Note the pressed-state fill deliberately uses `style={{backgroundColor}}`
(not a `bg-[var(--color-accent)]` Tailwind class) because the fill color is
per-dataset, not the single shared accent — same technique `FilterBar.tsx`
already uses for its category chip row (`categoryColor(cat)` via inline
`style`), so this is a reuse of an existing in-codebase pattern, not a new
one. Pressed-state text is white in both themes for legibility against all
three saturated fill colors (verify contrast at implementation; if any
token's dark-mode pastel value reads too light for white text, use
`--color-ink` as pressed-text color in dark mode instead — a one-line
conditional, not a design change).

**Icon size on the toggle button:** `size={20}` (20px), matching
`Header.tsx`'s existing icon-in-button sizing convention (`size={24}` is
used for the larger nav buttons; 20px here matches the button's own 20px
text more tightly, appropriate for a smaller inline chip-style control).

**Agent pulse:** extend `useAgentPulse`'s `PulseField` union with
`"overlay"` and wrap this `role="group"` div in the same `pulseClass`
treatment `FilterBar.tsx` already applies to its other groups (D-01's
"voice or click" parity requirement — an agent-driven overlay toggle must
visually pulse this control group exactly like a manual click would read
as "the same system").

### "Doesn't apply here" indicator (OVERLAY-05)

Resolves the visual-treatment discretion item: **dimmed but fully
interactive**, never `disabled` (D-01's "independent of active chart" lock
requires the buttons to stay settable even on non-timeline charts — a
caregiver may pre-set overlays before switching to BP Timeline).

```tsx
const activeChart = useFilters((s) => s.activeChart);
const overlayApplies =
  activeChart === "bp_timeline" || activeChart === "pulse_trend";

<div className={overlayApplies ? "" : "opacity-60"}>
  {/* toggle button row from above — always rendered, always clickable */}
</div>
{!overlayApplies && (
  <p aria-live="polite" className="mt-2 text-[18px] text-[var(--color-ink)]">
    Overlays aren&rsquo;t shown on this chart — switch to Blood Pressure or Pulse to see them.
  </p>
)}
```

`opacity-60` on the button row only (not the "Overlay:" label or the note
text) — the note itself stays full-opacity/full-contrast since it is the
important explanatory copy, not the thing being de-emphasized.

### Chart markers on `BPTimeline.tsx` / `PulseTrend.tsx` (D-06, OVERLAY-04)

One `ReferenceLine` per overlaid event, rendered **after** the existing
`Line`/`ReferenceArea` elements in JSX (z-order discipline both files
already document — bands/lines render in JSX order, markers must sit
visually on top). See Marker & Icon Contract above for the exact
icon/glyph/color per type and the primary/fallback rendering path.

Both charts need an identical `overlayEvents` prop addition — same shape,
same rendering block, so there is exactly one mental model for "what an
overlay marker looks like" regardless of which hero chart is active:

```tsx
export type OverlayEvent = {
  id: number;
  ts: number; // epoch ms; labs/procedures via parseDateOnly(date), incidents via new Date(datetime)
  type: "labs" | "incidents" | "procedures";
};
```

No hover/focus tooltip is added this phase (Claude's Discretion item,
resolved: skip it) — the accessible events table already provides full
detail per event (OVERLAY-06), and adding a second, chart-only detail
surface risks drifting toward OVERLAY-07's deferred "full detail in a
non-hover panel." A future phase can add a lightweight tooltip without
touching this contract.

### `OverlayEventsList.tsx` (new component, OVERLAY-06)

Directly templated on `ReadingsTable.tsx`'s accessible-table contract
(same big-button paging, plain-text-node, no-precision-input pattern) —
new file, new component, mirroring that file's structure line for line
where the shape allows.

**Conditional mount:** renders only when at least one overlay dataset is
ON (D-07's neutral default means nothing to show at first load — omit the
whole section, same convention `AgentStatusBanner` uses for its own
null-render default). Mounted in `App.tsx` after the `Readings` table
section, and — critically — **independent of `activeChart`**: it stays
visible on BP Categories/AM-PM just as much as on the timeline charts,
satisfying OVERLAY-06's "regardless of chart-marker accessibility limits."

**Columns:** `Date | Type | What happened | Notes` — one unified 4-column
table across all 3 resource shapes (vs. `ReadingsTable`'s 6 fixed-shape
columns), since labs/incidents/procedures don't share a column set the way
every `Reading` does.

| Column | Content per type |
|--------|-------------------|
| Date | Labs/Procedures: `fmtDateCell(parseDateOnly(date))` → "June 3, 2025" (date-only, no time — Pitfall 1 from RESEARCH, route through `parseDateOnly`, never bare `new Date()`). Incidents: `fmtDateCell + ", " + fmtTimeCell` → "June 3, 2025, 7:42 AM" (has a time component) |
| Type | Icon badge + word, using this phase's per-type icon/color (see Marker & Icon Contract) — same visual chip treatment as `ReadingsTable`'s BP-category chip (`inline-block rounded-full px-3 py-1 text-lg`, category color fill, white/contrast text) |
| What happened | Lab: `test_name` + (`result` ? " — {result} {unit}" : "") — e.g. "A1C — 5.4 mg/dL". Incident: `incident_type` + (`duration` ? " — {duration}" : "") — e.g. "Fall — 2 hours". Procedure: `procedure_name` + (`location` ? " — {location}" : "") + (`outcome` ? "; {outcome}" : "") — e.g. "MRI — City Hospital; Completed without complications" |
| Notes | `notes` value verbatim as a plain React text node (T-02-08 no-HTML-injection discipline, same as `ReadingsTable`'s existing notes row), or blank if null/empty |

**Sort:** newest-first across the merged list (by `ts`), same
`localeCompare`/numeric-descending convention `ReadingsTable` already uses.

**Pagination:** identical `PAGE_SIZE = 20`, "Show 20 more" button, reset
`visible` on data-array identity change (same `useEffect` pattern) — reuse
verbatim, do not reinvent.

**Per-type empty/error handling:** if the merged, ON-only event list is
empty, render the dynamic "No {list} recorded in this date range." message
(Copywriting Contract) in place of the table. If exactly one dataset's
query is in an error state, render its "Couldn't load {type}…" message as
a small `role="alert"` line above the table, but still render the table
with whichever other datasets succeeded — one failed fetch never blocks
the other two.

**Markup skeleton:**

```tsx
<section aria-label="Overlaid events">
  <h2 className="mb-4 text-2xl leading-tight font-bold text-[var(--color-ink)]">
    Overlaid events
  </h2>
  {errorNotes.map((msg) => (
    <p key={msg} role="alert" className="mb-2 text-[18px] text-[var(--color-ink)]">
      {msg}
    </p>
  ))}
  {events.length === 0 ? (
    <p className="text-[18px] text-[var(--color-ink)]">{emptyMessage}</p>
  ) : (
    <section className="rounded-lg bg-[var(--color-sky)] p-6">
      <table className="w-full text-left">
        <caption className="sr-only">Overlaid events</caption>
        <thead>
          <tr>
            <th scope="col" className="p-2 text-xl font-bold">Date</th>
            <th scope="col" className="p-2 text-xl font-bold">Type</th>
            <th scope="col" className="p-2 text-xl font-bold">What happened</th>
            <th scope="col" className="p-2 text-xl font-bold">Notes</th>
          </tr>
        </thead>
        <tbody>{/* rows, same shape as ReadingsTable's ReadingRow */}</tbody>
      </table>
      {/* "Show 20 more" / "Showing all N overlaid events" — verbatim reuse */}
    </section>
  )}
</section>
```
