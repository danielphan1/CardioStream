<objective>
Wire Plan 11-04's `GuideOverlay` into the app, and run the mandatory manual verification pass for
the phase's single load-bearing visual decision: the overlay stacking/layering contract locked by
`11-UI-SPEC.md` (opaque full-screen guide at `z-50`, CommandBar band promoted to `z-[60]` only
while the guide is open, no focus trap, `CommandBar` fully Tab-reachable throughout). This is the
closing composition step for the whole phase — GUIDE-01 through GUIDE-04 become end-to-end
observable only once this plan lands.

Purpose: D-01's entire premise — "the dashboard component tree stays mounted underneath" — is a
claim about `App.tsx`'s actual render tree, not something Plans 11-01 through 11-04 could verify
in isolation. This plan proves it, both by wiring (Task 1) and by a human visually confirming the
CSS stacking/scroll behavior jsdom cannot meaningfully assert (Task 2) — the same pattern this
codebase already uses for Recharts (09-06) and `window.speechSynthesis` (10-06), neither of which
has a real implementation in jsdom either.
Output: A fully wired dashboard where the Guide button (any of the three authenticated views)
opens a full-screen guide that never disturbs the live `CommandBar`/mic session, verified visually
end to end.
</objective>
