<objective>
Add the backend half of the new `toggle_guide` voice/text command (D-05): an eighth closed-union
member on the Claude-facing `AgentOutput.result` schema, the matching `AppliedFilters.guideOpen`
field, the fixed `toggle_guide_message` confirmation copy, the `interpret()` dispatch branch that
maps it to a server-composed reply, and the `SYSTEM_PROMPT` vocabulary that teaches the model the
command shape. `ToggleGuide` is a byte-for-byte structural mirror of the existing `ToggleSpeech`
(Phase 10) — explicit state only, never a flip/toggle — except its vocabulary is `open`/`closed`
(matching the overlay's own visibility semantics), not `on`/`off`. Per D-06, the prompt teaches
open/close ONLY — no section-name vocabulary that would imply deep-linking into the guide. Per
D-05, this is NOT a client-side keyword shortcut: the server `/agent` endpoint stays the sole
authority on command intent, exactly like every other voice command in this codebase (the
existing trust boundary documented in `frontend/src/lib/voice.ts`).

Purpose: GUIDE-03 requires the guide be "reachable and usable... by voice" without unmounting the
live voice session. This plan delivers the voice/text half of open/close (the click half is
Plan 11-04's Header button, and the "never unmounts" mechanism itself is Plan 11-05's App.tsx
wiring). Pure, mechanical extension of eight already-proven closed-union touch-points in this
file set (Phase 9/10 precedent) — no new architecture, no new library, no new route.
Output: `ToggleGuide` round-trips through `AgentOutput`, `interpret()` maps it to
`AppliedFilters(guideOpen=...)`, and the system prompt routes open/close utterances to it.
</objective>

| SYSTEM_PROMPT vocabulary scope | The new paragraph must not teach the model a broader command surface than D-06 allows (open/close only) — an over-broad prompt would let a future model version invent section-jump behavior GUIDE-05 explicitly reserves for v2 |

|-----------|----------|-----------|-------------|-----------------|
