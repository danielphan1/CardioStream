<objective>
Give the Command Bar the new "contrasting feature panel" identity `13-UI-SPEC.md` §Component Language item 3 calls for — using the dedicated `var(--color-panel)` token (App.tsx's wrapper band) instead of `var(--color-mist)` like every other surface, since DESIGN.md already names the Command Bar "the app's one truly distinctive component" and it is the product's core value proposition (voice-first input). `--color-panel` (defined in Plan 13-01) is a purpose-built, non-theme-inverting dark background — NOT `var(--color-depth)`, which is the ink/text token and inverts per theme by design (dark navy in light theme, near-white in dark theme); reusing it as a panel background would make the panel correctly dark in light theme but the single brightest surface on the page in dark theme, defeating the "dark instrument panel in both themes" intent. Re-skin the rest of `App.tsx` (Dashboard skeleton/error states, ReadingsTable section heading, Upload/Records view backgrounds) to the new tokens in the same pass since both files are edited together by design (this specific design decision spans both files, per `13-PATTERNS.md`'s explicit flag).

Purpose: because CommandBar's background is switching from an inherited light Mist band to a dark Panel band, every piece of text/border inside CommandBar that currently has NO independent chip background (relies on inheriting the light band behind it) would become illegible without an explicit flip — this plan works out and applies that flip precisely, using only already-WCAG-verified token pairs (`--color-panel`/`--color-panel-text`, contrast-verified in Plan 13-01 at 15.90:1 light / 18.44:1 dark).
Output: App.tsx and CommandBar.tsx fully re-skinned; CommandBar reads as a deliberate dark instrument panel in both themes with legible text throughout.
</objective>
