# Phase 13 — UI Design Contract

> Visual and interaction contract for the full visual-identity replacement described in `13-CONTEXT.md` (D-01 through D-09, locked). This is NOT an evolution of Phase 12's "Airy Nautical"/"Night Sea" system — every hex, radius, shadow, and type value below is new. What carries forward is documented in `13-CONTEXT.md` as *behavior*, not visuals: the nautical motif (as a continuation, per D-02), the accessibility floor (D-06), the never-color-alone rule (D-07), the mechanism (CSS custom properties + Tailwind utility classes, per "Reusable mechanism"), and the medical/data semantic role of clinical + overlay colors (D-08 — new hex values, same meaning).
>
> Creative North Star for this phase: **"Slack Water"** (light theme) / **"Night Watch"** (dark theme) — a premium marine-instrument-panel aesthetic (chart paper, brass fittings, signal lights), not a beach-themed or skeuomorphic one (D-03). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Spacing Scale

Unchanged from the current system — no creative pressure to alter it, and `13-CONTEXT.md` D-06 requires the 48px click-target floor (`2xl`) to survive regardless of new visual world. Declared fresh here as this phase's own contract, not inherited by reference.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing, chip gaps |
| md | 16px | Default element spacing, card gutters |
| lg | 24px | Section padding, card internal padding |
| xl | 32px | Layout gaps, generous section padding |
| 2xl | 48px | Major section breaks — **also the accessibility click-target floor (non-negotiable, D-06)** |
| 3xl | 64px | Page-level side gutters at wide viewports |

Exceptions: **none.** Every interactive control is ≥48×48px — no sub-floor carve-out for any header/utility control (this phase removes the prior system's ambiguous "six discreet header controls" exception language; CLAUDE.md's ≥48px constraint is unconditional).

## Typography

Two type families, two weights total, exactly 4 sizes. Body stays at the 18px floor (non-negotiable, D-06) — the choice to move off Atkinson Hyperlegible is a disclosed, deliberate call under D-09's creative latitude on type choice (not something the accessibility floor mandates a specific typeface for): Inter is chosen for its very high x-height/aperture legibility (proven at accessibility-first products), and its "clean sans" character matches the genre reference's "clean geometric sans-serif type" (D-04) far better than the outgoing display/label face. Space Grotesk is added **only** for large numeric hero values (stat-card values) — its even digit widths read as "precision instrument," reinforcing the marine-instrument-panel concept exactly where the structural reference (D-04) calls for a prominent large value.

| Role | Size | Weight | Line Height | Family |
|------|------|--------|-------------|--------|
| Body | 18px | 400 (Regular) | 1.5 | Inter |
| Label | 20px | 600 (Semibold) | 1.25 | Inter |
| Heading | 24px | 600 (Semibold) | 1.2 | Inter |
| Display | 36px | 600 (Semibold) | 1.15 | Space Grotesk |

**The Two-Weight Rule (carried forward, re-scoped):** only 400 and 600 are used anywhere, across both families. Load exactly: Inter 400 + Inter 600 (variable font subset acceptable) + Space Grotesk 600. Do not introduce a third weight or a third family.

**Where Space Grotesk appears:** exclusively the large numeric value inside a stat card (e.g. the BP average, pulse average, reading count) and nowhere else — not section headings, not buttons, not body copy. This keeps the system's "one typeface does everything except this one accent moment" discipline the old system had, just re-pointed at a new pair.

**New dependencies to add:** `@fontsource/inter`, `@fontsource/space-grotesk` (self-hosted, matches the existing `@fontsource/atkinson-hyperlegible` pattern — no external font CDN, consistent with the project's no-third-party-requests posture). `@fontsource/atkinson-hyperlegible` may be removed once migration is complete — flag as a planning-time cleanup task, not a same-commit deletion (avoid breaking anything mid-migration).

| Dominant (60%) | `#F5F7F6` / `#0A121F` | Page background (`--color-deck`) |

**Destructive note:** the product has no true delete/destroy action today (confirmed in the outgoing DESIGN.md). `--color-hazard` is reserved for if one is added later (e.g. a future "delete record" action). ## Elevation & Shape (new values, same mechanism)

The Flat-Sea mechanism carries forward unchanged (full-width command/filter bands stay flat; only discrete "island" surfaces — stat tiles, dialogs, tooltips — get the one shadow token), retuned for a softer, more diffuse "premium dashboard" feel per the structural reference (D-04: "soft diffuse shadows on cards only, flat elsewhere"):

```css
:root {
  --shadow-elevation: 0 8px 24px -4px rgba(16, 28, 46, 0.10),
                       0 2px 6px -2px rgba(16, 28, 46, 0.06);
}
.dark {
  --shadow-elevation: 0 8px 24px -4px rgba(0, 0, 0, 0.45),
                       0 0 0 1px rgba(231, 238, 242, 0.05);
}
```

Radii — three named tokens, same purpose split as before, values bumped toward the reference's "soft rounded corners ~12–16px" range:

| Token | Value | Usage |
|---|---|---|
| `lg` | 8px | Secondary header-chrome controls only (theme toggle, Guide/Upload/Log-out utility buttons) |
| `xl` | 14px | Default for everything else interactive/containing — cards, dialogs, tooltips, inputs, filter/overlay buttons |
| `full` | 9999px | Reserved for data-bearing chips only (BP-category and overlay-dataset pills) |

`--band-opacity` (BPTimeline's decorative-tint bands, exempt from the contrast floor per the precedent at `BPTimeline.tsx` ~line 46): keep the existing starting values (0.10 light / 0.14 dark) against the new category hex values — this is a decorative/exempt element, so the executor should eyeball-verify legibility against the new palette rather than treat these two numbers as re-locked.

## Component Language & Structural Mapping

This is the phase's genuinely open design question (per `13-CONTEXT.md` D-04/D-05) — how the structural reference's card language maps onto this app's actual single-column, full-width-band layout (not a sidebar-nav shell). Resolved here so planning doesn't have to re-litigate it:

1. **No sidebar rail.** Confirmed deferred per D-05 and `13-CONTEXT.md`'s own Deferred Ideas list. The DOM structure stays: header → command bar → filter bar → content, single centered column below the full-width bands. Only surface treatment changes, not layout topology.

2. **Stat-card language (StatsStrip.tsx) adopts the reference's icon + value + sparkline + status-pill pattern:**
   - Icon: 24px lucide-react icon, Depth-colored, top-left of the card.
   - Label: Label typography (20px/600 Inter), e.g. "Avg. Systolic."
   - Value: Display typography (36px/600 Space Grotesk) — the one place this font appears.
   - Inline sparkline: a small (≈32–40px tall) decorative Recharts area/line reusing that metric's own chart-series or category color at reduced opacity, `aria-hidden="true"` — it summarizes a trend the full chart below already exposes accessibly, mirroring the existing `BPTimeline.tsx` decorative-tint exemption precedent (ambient, not a second source of truth). **This is a new sub-component, not present in the current `StatsStrip.tsx` — flag for `gsd-planner` as new build work, not a re-skin.**
   - Status pill: reuse the existing category-chip mechanism verbatim (full radius, solid category fill, chip text, word label like "Normal") — satisfies D-07 without inventing a new state-encoding pattern.
   - Card shell: Mist background, `xl` (14px) radius, the one elevation shadow, 24px internal padding (unchanged from outgoing system's card-surface spec).

3. **The "contrasting feature panel" (D-04) maps onto the Command Bar, not a new element.** DESIGN.md already names the Command Bar "the app's one truly distinctive component" — it is also, not coincidentally, the product's core value proposition (voice-first input). Giving it the reference's one dark/contrasting panel treatment (Depth-toned surface, Brass accent details, against the lighter Deck/Mist surfaces around it) makes the visual hierarchy match the product's actual priority: the thing Chris talks to is the thing that visually anchors the screen. No new navigation chrome is introduced to host this panel — it reuses the existing full-width band between header and filter bar.

4. **Cards/dialogs/tooltips:** Mist background, `xl` radius, elevation shadow; borders stay 2px solid Depth for the un-filled/inactive identity (unchanged mechanism from the outgoing system — a proven, already-accessible pattern, not reinvented this phase). Dashed-border-for-disabled convention (`2px dashed`) carries forward unchanged.

## Copywriting Contract

This phase replaces visuals, not voice or content — `13-CONTEXT.md`'s creative-freedom grant (D-09) covers palette/type/component form/composition, not copy. Every string below is carried over **verbatim** from the current implementation; sourced by direct grep, not invented.

| Element | Copy |
|---------|------|
| Primary CTA | **"Show all data"** (`EmptyState.tsx`) — the app's one guaranteed, singular CTA per the D-11 empty-state escape-hatch rule. Other action labels ("Apply," "Add Record," "Upload," "Log out") carry over unchanged. |
| Empty state heading | "No readings match these filters" (`EmptyState.tsx`) |
| Empty state body | "There are no {AM\|PM }readings in {presetLabel}{ in {category}}.{ The newest reading is from {date}.}" — dynamic, AM/PM and category clauses omitted when filter is "all" (`EmptyState.tsx`) |
| Error state | "Couldn't reach the assistant — use the filters and buttons below instead." (`CommandBar.tsx` `OFFLINE_COPY`) and "Enter a date like 2025-06-13" (`DateRangePicker.tsx` inline validation) — both follow the app's fixed rule: plain-language problem + immediate next step, raw error/stack text is never rendered. |
| Destructive confirmation | "Log out?" / "You'll need the password to unlock the dashboard again." — buttons "Cancel" / "Log out" (`Header.tsx` `LogoutConfirmDialog`). Confirm button uses Brass (accent), not Hazard — logging out isn't data-destructive. |

No copy changes are in scope for this phase. If a new component (e.g. the StatsStrip sparkline) needs new copy (an `aria-label` for the icon, etc.), it should follow the same plain-language, never-color-alone, never-raw-error discipline documented above.
