# Phase 12 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope reminder (D-01/D-02):** This is an *evolution*, not a replacement, of `frontend/src/index.css`'s existing "airy nautical" (light) / "night sea" (dark) token system. Only four things change sitewide: (1) `--color-accent`/`--color-accent-text`, (2) new elevation/shadow tokens, (3) a `rounded-lg`→`rounded-xl` radius bump, (4) formalizing today's ad-hoc type scale into named `--text-*` tokens at the SAME rendered sizes. Everything else in this document (clinical colors, focus color, motion, copy) is stated explicitly as **unchanged** so the checker/executor never has to guess.

## Spacing Scale

Declared values (must be multiples of 4) — **unchanged, already the established convention**, confirmed by codebase scan (`gap-*`/`p-*`/`px-*`/`py-*` across all `components/*.tsx`, `components/charts/*.tsx`, `components/records/*.tsx`):

| Token | Value | Usage | Evidence in codebase |
|-------|-------|-------|-----------------------|
| xs | 4px | Icon gaps, inline padding | `gap-1`, `py-1` |
| sm | 8px | Compact element spacing | `gap-2` (72×), `p-2` (42×), `py-2` (19×) |
| md | 16px | Default element spacing | `px-4` (50×), `gap-4` (38×), `p-4` (13×) |
| lg | 24px | Section padding | `px-6` (26×), `p-6` (22×), `gap-6` (5×) |
| xl | 32px | Layout gaps | `px-8` (8×), `gap-8` (6×), `py-8` (4×), `p-8` (4×) |
| 2xl | 48px | Major section breaks / **the ≥48px accessibility target floor** | `min-h-12` (67×), `min-w-12` (5×) |
| 3xl | 64px | Page-level spacing | `px-16` (6×) |

Non-8pt intermediate values already in use and compliant with the "multiples of 4" rule (not exceptions, just finer-grained): `px-3`/`gap-3` (12px), `px-5` (20px).

**Exceptions:** none. This phase does not touch `min-h-12`/`min-w-12` — confirmed as a hard floor per RESEARCH.md Pitfall 4 (a corner-radius bump changes how a button *looks*, never its computed height/width). Any diff that shrinks a `min-h-12`/`min-w-12` class is out of contract and must be rejected at review.

## Elevation & Surface Treatment (D-05 — new this phase)

The existing `--band-opacity` per-theme custom property (already in `index.css`, used by `.chart-band`) is the established pattern for a themed value that has no static Tailwind equivalent. `--shadow-elevation` follows the same pattern:

```css
:root {
  --shadow-elevation: 0 4px 10px -2px rgba(20, 33, 61, 0.12),
                       0 2px 4px -2px rgba(20, 33, 61, 0.08);
}
.dark {
  /* flat black shadow reads as near-invisible on #0B1626/#13233A — pair a
     low-opacity black shadow with a 1px light hairline to fake an
     edge-highlight, per Material Design's dark-theme elevation guidance */
  --shadow-elevation: 0 4px 10px -2px rgba(0, 0, 0, 0.5),
                       0 0 0 1px rgba(232, 241, 239, 0.06);
}
```

| Property | Before | After | Applies to |
|----------|--------|-------|-----------|
| Corner radius | `rounded-lg` (8px) | `rounded-xl` (12px) | App-owned surfaces only: cards, panels, chart containers, filter bar (StatsStrip, ReadingsTable, OverlayToggle, EmptyState, ChartTooltip, filter chips, AddRecordPage sections, etc.) |
| Shadow | none on ~19/20 components; `shadow-lg` in exactly one place (`ChartTooltip.tsx`) | `shadow-[var(--shadow-elevation)]` on the same app-owned surfaces listed above | Same surface list |
| Spacing rhythm | existing 8pt scale | unchanged values, applied slightly more generously between sections per D-05 ("more breathing room") — use `xl`(32px)/`2xl`(48px) tokens for section-level gaps where `lg`(24px) is used today, not a new scale | Section-level gaps only, not component-internal padding |

**Third-party widget scope (RESEARCH.md Pitfall 3):** `react-day-picker` (`DateRangePicker.tsx`, `SingleDateField.tsx`) bridges only `--rdp-accent-color`/`--rdp-accent-background-color`/`--rdp-day-width`/`--rdp-day_button-width`/`height` today. D-05's radius/shadow bump is scoped to **app-owned surfaces** (CONTEXT.md's own D-05 text: "cards, panels, chart containers, filter bar" — the calendar isn't named). Decision: leave the DayPicker's internal day-cell/month-nav chrome as-is; only its accent color updates automatically (it already reads `var(--color-accent)` through the existing `--rdp-accent-color` bridge). Do not add new `--rdp-*` radius/shadow bridges this phase — treat the calendar as an intentionally distinct third-party visual.

## Typography

Existing ad-hoc scale (`text-[18px]`, `text-lg`, `text-[20px]`, `text-xl`, `text-2xl`, `text-[32px]` — mixed arbitrary/named, confirmed by grep across all components) is **formalized into 4 named `--text-*` tokens at the exact same rendered sizes** — no visual size change, only naming consistency for future edits:

| Role | Size | Weight | Line Height | Token | Note |
|------|------|--------|-------------|-------|------|
| Body | 18px | 400 (regular) | 1.5 | `--text-base` (existing, unchanged) | ACC-01 floor — `body{}` rule in `index.css`; never touched |
| Label / Control | 20px | 700 (bold) | 1.25 | `--text-control` (NEW) | Today's de facto button/label/chip size (`text-[20px]`, 71 occurrences) — formalized, not resized |
| Heading | 24px | 700 (bold) | 1.25 | `--text-h2` (NEW) | Today's `text-2xl` section headings — formalized, not resized |
| Display | 32px | 700 (bold) | 1.25 | `--text-h1` (NEW) | Today's `text-[32px]`/`text-[2rem]` (Header.tsx app title, StatsStrip vital values) — formalized, not resized |

```css
@theme {
  --text-base: 1.125rem;              /* existing — 18px body floor, ACC-01 */
  --text-control: 1.25rem;             /* NEW — 20px */
  --text-control--font-weight: 700;
  --text-control--line-height: 1.25;
  --text-h2: 1.5rem;                   /* NEW — 24px */
  --text-h2--font-weight: 700;
  --text-h2--line-height: 1.25;
  --text-h1: 2rem;                     /* NEW — 32px */
  --text-h1--font-weight: 700;
  --text-h1--line-height: 1.25;
}
```

Exactly 2 weights declared (400, 700) — matches the font family's only two shipped static weight files; do not introduce a synthesized/faux-bold intermediate weight.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-foam` — light `#F2F7F5` / dark `#0B1626` | Page background (unchanged) |
| Secondary (30%) | `--color-sky` — light `#E2EDF2` / dark `#13233A` | Cards, panels, chart containers, filter bar surface (unchanged) |
| Accent (10%) | `--color-accent` — light **`#B94927`** / dark **`#DA6F4E`** (CHANGED — replaces navy `#14213D`/`#8FC1D4`) | See reserved-for list below |
| Destructive | not applicable this phase | No destructive actions exist in v1.1 scope (edit/delete on records is explicitly out of scope per REQUIREMENTS.md); existing error states use ink-on-sky + `TriangleAlert` icon, not a separate red token — unchanged by this phase |

**Accent reserved for (D-03 — sitewide one-for-one swap of every existing navy `var(--color-accent)`/`var(--color-accent-text)` consumer, not a second token layered alongside it):**
- Primary action buttons: `AddRecordPage.tsx` submit button, `EmptyState.tsx` "Show all data" button, `UploadPage.tsx` submit
- Active/pressed toggle fills: `OverlayToggle.tsx`, `FilterBar.tsx` AM/PM and BP-category pills, Header.tsx Guide/Voice-Replies toggles when ON
- Active filter chips
- Any other element currently rendering `var(--color-accent)`/`var(--color-accent-text)` — grep `index.css` consumers before landing, do not add new consumers beyond today's set

**Accent hex derivation (supersedes RESEARCH.md's draft candidates with a more rigorous check — see below):**

```css
:root {
  /* was: --color-accent: #14213D; */
  --color-accent: #B94927;        /* terracotta — 5.19:1 vs white text, 4.80:1 vs foam, 4.36:1 vs sky */
  --color-accent-text: #FFFFFF;    /* unchanged */
}
.dark {
  /* was: --color-accent: #8FC1D4; */
  --color-accent: #DA6F4E;        /* coral-salmon — 5.50:1 vs accent-text, 4.79:1 vs sky (dark) */
  --color-accent-text: #0B1626;    /* unchanged */
}
```

Both values computed and verified in this research session (WCAG 2.1 relative-luminance formula, hand-run in Node, cross-checked against the codebase's own hex values — not copy-pasted from RESEARCH.md's draft):
- **Contrast:** clears AA 4.5:1 (text-on-accent) and AA 3:1 (accent-as-border/ring against `--color-foam`/`--color-sky`) in both themes with headroom.
- **Hue-collision check (RESEARCH.md Pitfall 1) — extended beyond research's single `--cat-stage1` spot-check to all 6 `--cat-*` + 3 `--overlay-*` tokens in both themes:** research's own draft candidates (`#A3402A`/`#D9633F`) were re-verified during this session and found to sit within the 10°-hue/10pp-lightness collision box of `--cat-stage2` (light: hue Δ8°, lightness Δ1pp — a closer near-miss than the `--cat-stage1` collision research documented). The values above (hue 14°, light L44/dark L58) were chosen specifically to clear **every** clinical/overlay token's collision box in both themes (nearest neighbor is `--cat-stage2`/`--cat-crisis` at hue Δ11°, comfortably outside the 10° threshold). Given how crowded the 0–45° warm range already is, this is real headroom, not a wide margin — the non-color-only encoding convention (word/icon + `aria-pressed` on every category chip and toggle) remains the backstop, per RESEARCH.md's own conclusion.

**`--color-focus` stays untouched (RESEARCH.md Pitfall 2):** light `#1D4E89` / dark `#8FC1D4` — a separate token from accent, coincidentally equal to the *old* dark-mode accent today. After this swap, focus rings and the new accent visibly diverge for the first time in dark mode — a net accessibility improvement (focus indicators no longer blend into accent-colored buttons), not a regression. Do not touch `--color-focus` in the same diff as the accent swap.

**Clinical/locked tokens — explicitly out of scope, do not touch (D-04):** `--cat-hypotension` through `--cat-crisis`, `--band-opacity`, `--cat-chip-text`, `--overlay-labs`/`--overlay-incidents`/`--overlay-procedures`, `--overlay-chip-text`, `--line-systolic`/`--line-diastolic`/`--ref-bradycardia`. These carry medical/data significance (AHA BP classification, overlay dataset identity), not aesthetic choice.
