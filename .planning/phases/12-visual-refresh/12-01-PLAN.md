<objective>
Land the token-level foundation every other Phase 12 plan depends on (D-01: this is an evolution of the existing token system, not a from-scratch palette replacement): replace the navy `--color-accent`
(light `#14213D` / dark `#8FC1D4`) with the UI-SPEC-locked warm terracotta/coral-salmon pair (light
`#B94927` / dark `#DA6F4E`, D-02/D-03 — warmth comes from this accent swap, not a typography change), add a themed `--shadow-elevation` custom property mirroring the
codebase's existing `--band-opacity` per-theme pattern (D-05), and formalize three ad-hoc pixel sizes
already in use (20px control labels, 24px section headings, 32px display text) into named `--text-control`/
`--text-h2`/`--text-h1` `@theme` tokens with NO rendered-size change (D-06). Add the `wcag-contrast`
devDependency and a new `frontend/src/tests/contrast.test.ts` proving the new accent pair clears WCAG AA
in both themes (VISUAL-02a).

Every downstream Phase 12 plan (12-02 through 12-07) consumes these tokens by Tailwind utility class name
(`rounded-xl`, `shadow-[var(--shadow-elevation)]`, `text-control`, `text-h2`, `text-h1`) or automatically via
already-present `var(--color-accent)` references — none of them can start meaningfully before this plan lands,
which is why it is the sole Wave 1 plan.

Purpose: this is the single point of change (per RESEARCH.md's architecture diagram) that every one of the
~20 consuming components picks up automatically at paint/build time — no component invents a new color or
size literal.
Output: an updated `index.css` token system, a new `contrast.test.ts` regression test, and the
`wcag-contrast` devDependency.
</objective>
