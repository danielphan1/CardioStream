<objective>
Build the non-visual foundation Phase 8's forms sit on: byte-accurate TS mirrors of Phase 7's
three create/read schemas, typed POST wrappers reusing the existing `postJson` path, a promoted
single-source date-validity function, a new `combineLocalDateTime` helper for Incident's
date+time merge, a reusable single-date input component (extracted from the range-only
`DateRangePicker`), and the three `useMutation` hooks the forms will call.

This plan touches zero UI a caregiver will see — it is pure interface/contract work so Plan 08-02
(field-sets) and Plan 08-03 (page container + nav) can be written against a fixed, already-typed
surface instead of inventing shapes ad hoc.

Purpose: give every later plan in this phase one unambiguous contract for "how do I build and
send a Lab/Incident/Procedure creation request" — no plan after this one should need to touch
`api/types.ts`, `api/client.ts`, or `lib/dates.ts` again.
Output: `LabResult(Create)`/`Incident(Create)`/`Procedure(Create)` types, `postLab`/`postIncident`/
`postProcedure`, `isValidDateText`/`combineLocalDateTime`, `SingleDateField`, `useCreateLab`/
`useCreateIncident`/`useCreateProcedure`.
</objective>
