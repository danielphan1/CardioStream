# Phase 8 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase adds one new caregiver surface: an "Add Record" view with a 3-way
type switcher (Lab / Incident / Procedure) and three field-sets that POST to
Phase 7's already-shipped endpoints. It does **not** introduce a new visual
language — the project has a locked, comprehensively documented design system
(`frontend/src/index.css`, header comment: "Design-token system — 02-UI-SPEC.md
locked palette"), and 08-CONTEXT.md/08-RESEARCH.md already pin nearly every
visual decision to an exact existing component to mirror (`FilterBar`'s
segmented control, `DateRangePicker`'s date-entry pattern, `UploadPage`'s
confirmation/error sections, `Header`'s discreet nav-button styling). No
shadcn gate was raised, for the same reason Phase 6 skipped it: this is a
continuation phase on an already-shipped, deliberately hand-rolled Tailwind
system, not a greenfield init — introducing shadcn now would fork the visual
language mid-project for three small forms.

This document resolves the remaining open items CONTEXT.md explicitly left to
"Claude's Discretion" (exact copy, field contracts, icon assignment, max
lengths, field-set header treatment) so the executor has zero visual
ambiguity left to invent at implementation time.

## Accessibility Scope (locked by RESEARCH, restated here for the executor)

This page is caregiver data-admin, like `UploadPage` — **exempt from the
voice-operability mandate** (PROJECT.md's "every feature operable by voice"
is scoped to Chris's primary dashboard surface; voice/agent-driven data entry
is AGENT-02, deferred to v2). It is **NOT exempt from the ≥48px / ≥18px /
high-contrast / keyboard-navigable / no-drag-or-precision floor** — OVERLAY-02's
requirement text locks that explicitly. Every form control below (text
inputs, date field, time input, textarea, segmented control, Submit button)
must be `min-h-12` (48px) and keyboard-operable. Only the Header's "Add
Record" **nav** button (not the form controls inside the page it opens)
inherits the existing discreet-zone exemption already applied to
Upload/Log out (occasional caregiver admin, never operated by Chris).

## Spacing Scale

Declared values (multiples of 4), as already used throughout the codebase:

| Token | Value | Usage in this phase |
|-------|-------|-------|
| xs | 4px | Icon-to-glyph micro-gaps within labels |
| sm | 8px | Compact gaps (`gap-2`) inside the type-switcher `role="group"` row |
| md | 16px | Card padding on confirmation/error sections (`p-6` uses lg, see below); field-set header icon-to-text gap |
| lg | 24px | Vertical gap between stacked form fields within a field-set (`gap-6`… see note) |
| xl | 32px | Vertical rhythm between major page sections — heading block, switcher, field-set, submit/confirmation (`gap-8` on the page's outer flex column, mirrors `UploadPage`'s `max-w-[720px] flex flex-col gap-8` wrapper exactly) |
| 2xl | 48px | Minimum interactive target height on every form control (`min-h-12`) — non-negotiable this phase (see Accessibility Scope) |
| 3xl | 64px | Page-level side gutters at ≥1280px (`xl:px-16`, inherited from the shared page-wrapper convention) |

**Field-to-field gap within one field-set:** `gap-4` (16px) — matches
`DateRangePicker`'s own `flex flex-col gap-4` wrapper exactly (the field-set
components are a direct structural sibling of that pattern).

Exceptions: none new. Reuses the existing `gap-3` (12px) icon-to-text
exception already established in `UploadPage`/`AgentStatusBanner` for
confirmation/error icon rows.

## Typography

Full system (existing, reused). This phase uses Body, Label, and Heading
roles — no new type role introduced.

| Role | Size | Weight | Line Height | Used for in this phase |
|------|------|--------|-------------|------------------------|
| Body | 18px | 400 (regular) | 1.5 | Intro paragraph, confirmation/error sentences, placeholder/helper text |
| Label | 20px | 700 (bold) | 1.2 | Form field labels, type-switcher button text, Submit button text, field-set subsection headers (h3) |
| Heading (h2) | 24px | 700 (bold) | 1.2 | Page title "Add a record" (mirrors `UploadPage`'s "Add new readings" h2 exactly) |
| Display | 32px | 700 (bold) | 1.2 | Not used this phase (reserved for `Header`'s h1) |

**Field-set subsection headers use the Label role (20px/700), not a second
Heading size** — this keeps a clear two-level hierarchy (page h2 24px >
field-set h3 20px > body/labels 18-20px) without inventing a new size,
consistent with the "3-4 sizes max" contract.

## Color

| Role | Value (light / dark) | Usage |
|------|------|-------|
| Dominant (60%) | `--color-foam` (`#F2F7F5` / `#0B1626`) | Page background |
| Secondary (30%) | `--color-sky` (`#E2EDF2` / `#13233A`) | Confirmation card surface, inactive segmented-button/input backgrounds |
| Accent (10%) | `--color-accent` (`#14213D` / `#8FC1D4`) | Reserved for, in this phase: the **active** type-switcher segment (Lab/Incident/Procedure — `aria-pressed=true`), and the **enabled** Submit button fill |
| Destructive | none — this project has no separate destructive/danger color | Not applicable; this phase has no destructive action (see Copywriting Contract) |

**Accent reserved-for list (closed, extends the existing project-wide list
from `06-UI-SPEC.md` with this phase's two additions):** Send button (agent),
active/pressed filter chips (date/AM-PM/BP-category), CommandBar's
listening-state ring, Log-out confirm button, **and now: the active
Lab/Incident/Procedure segment, and the enabled Submit button.** Everything
else in this phase (inputs, inactive switcher segments, disabled Submit,
field-set headers) uses `--color-ink` text/border on `--color-foam` or
`--color-sky` — never accent.

**Explicit prohibition (inherited, not re-negotiated):** no `--cat-*`
clinical category token anywhere in this phase's forms — those are reserved
exclusively for blood-pressure clinical severity, unrelated to labs/
incidents/procedures.

## Field Contracts

All labels use the Label typography role (20px/700). All controls are
`min-h-12` (48px). Text/number inputs reuse `DateRangePicker`'s exact
`inputClass`: `min-h-12 rounded-lg border-2 border-[var(--color-ink)]
bg-[var(--color-foam)] px-3 text-[18px] text-[var(--color-ink)]`. Textareas
use the same classes plus `min-h-24 py-2` (multi-line) and inherit
`maxLength` from the JSX attribute (not client-rejected — just capped
input, per CLAUDE.md-cited Phase 7 accepted-risk on unbounded backend text).

### Lab

| Field | Label | Control | Required | Validation / Max | Placeholder |
|-------|-------|---------|----------|-------------------|-------------|
| `date` | Date | `SingleDateField` (typed `YYYY-MM-DD` + oversized calendar) | Yes | `isValidDateText` round-trip (Pattern 2) | `YYYY-MM-DD` |
| `test_name` | Test name | text input | Yes | maxLength 200 | "e.g. A1C, Cholesterol panel" |
| `result` | Result | text input, `inputMode="decimal"` | No | empty OR `Number.isFinite(Number(text))` — non-empty-but-non-numeric blocks Submit (Pitfall 3 guard) | "e.g. 5.4" |
| `unit` | Unit | text input | No | maxLength 20 | "e.g. mg/dL" |
| `range_low` | Normal range — low | text input, `inputMode="decimal"` | No | same numeric gate as `result` | "e.g. 4.0" |
| `range_high` | Normal range — high | text input, `inputMode="decimal"` | No | same numeric gate as `result` | "e.g. 6.0" |
| `notes` | Notes | textarea | No | maxLength 1000 | "Optional notes" |

### Incident

| Field | Label | Control | Required | Validation / Max | Placeholder |
|-------|-------|---------|----------|-------------------|-------------|
| `datetime` (date half) | Date | `SingleDateField` | Yes | `isValidDateText` round-trip | `YYYY-MM-DD` |
| `datetime` (time half) | Time | native `<input type="time">`, `min-h-12`, same border/bg classes as `inputClass` | Yes | presence-only (`timeText !== ""`) — format is browser-guaranteed (Pitfall 4) | — |
| `incident_type` | What happened | text input (free text — backend has no fixed enum, `incident_type: str`) | Yes | maxLength 200 | "e.g. Fall, Hospitalization, Seizure" |
| `duration` | Duration | text input | No | maxLength 100 | "e.g. 2 hours, 3 days" |
| `notes` | Notes | textarea | No | maxLength 1000 | "Optional notes" |

**Combining date + time:** build the request field as `` `${dateText}T${timeText}:00` `` (always append `:00` seconds for consistency with this codebase's existing naive-local format) — **never** `.toISOString()` (Pitfall 5: appends `Z`/UTC-converts, violating DATA-05's naive-local-everywhere contract).

### Procedure

| Field | Label | Control | Required | Validation / Max | Placeholder |
|-------|-------|---------|----------|-------------------|-------------|
| `date` | Date | `SingleDateField` | Yes | `isValidDateText` round-trip | `YYYY-MM-DD` |
| `procedure_name` | Procedure name | text input | Yes | maxLength 200 | "e.g. MRI, Catheter change" |
| `location` | Location | text input | No | maxLength 200 | "e.g. City Hospital" |
| `outcome` | Outcome | text input | No | maxLength 200 | "e.g. Completed without complications" |
| `notes` | Notes | textarea | No | maxLength 1000 | "Optional notes" |

**Every optional numeric field must be included in the Submit-gating
validity check, not just the required fields** — a non-empty-but-non-numeric
`result`/`range_low`/`range_high` must block Submit exactly like an invalid
required field would (Pitfall 3: `JSON.stringify(NaN)` silently becomes
`null`, causing silent data loss otherwise).

## Phase-Specific Component Contract

*(Additional detail beyond the standard template — the executor's primary visual reference.)*

### Header nav (3-state, resolves the binary-toggle gap — RESEARCH Pattern 1)

`Header.tsx`'s current toggle is binary (`onDashboard ? "Upload" : "Back to
dashboard"`). Extend to three states exactly as follows — do not nest more
ternaries onto the existing binary shape (Pitfall 1):

```tsx
const onDashboard = view === "dashboard";

{onDashboard ? (
  <>
    <button type="button" onClick={() => go("upload")} /* existing, unchanged */>
      <Upload aria-hidden="true" size={24} />
      Upload
    </button>
    <button
      type="button"
      onClick={() => go("records")}
      className="flex items-center gap-2 rounded-lg border-2 border-[var(--color-ink)] bg-[var(--color-sky)] px-4 py-2 text-[20px] font-bold text-[var(--color-ink)]"
    >
      <ClipboardPlus aria-hidden="true" size={24} />
      Add Record
    </button>
  </>
) : (
  <button type="button" onClick={() => go("dashboard")} /* existing, unchanged */>
    <Upload aria-hidden="true" size={24} />
    Back to dashboard
  </button>
)}
```

Both "Upload" and "Add Record" show together on the dashboard; either
non-dashboard view shows only "Back to dashboard" — no direct upload↔records
cross-link (matches the existing single-back-link convention). Both buttons
keep the discreet caregiver-zone styling (2px ink border, sky surface,
icon+text, exempt from 48px) already applied to Upload/Log out.

### AddRecordPage.tsx layout (top to bottom)

```
<main className="mx-auto flex max-w-[720px] flex-col gap-8 bg-[var(--color-foam)] px-4 py-8 md:px-8 xl:px-16">
  h2 "Add a record"                                    (24px/700, mirrors UploadPage's h2)
  p  intro sentence                                     (18px/400)
  role="group" aria-label="Record type"                 (type switcher — see below)
  field-set (h3 + icon + fields, key={type+resetSeq})   (see Field Contracts)
  Submit button                                          (aria-disabled until canSubmit)
  confirmation OR error region                          (role="status" / role="alert")
</main>
```

**Type switcher:** mirrors `FilterBar`'s exact `inactiveClass`/`activeClass`
constants verbatim:
```tsx
const inactiveClass = "min-h-12 rounded-lg px-4 text-[20px] font-bold bg-[var(--color-sky)] text-[var(--color-ink)] border-2 border-[var(--color-ink)]";
const activeClass = "min-h-12 rounded-lg px-4 text-[20px] font-bold bg-[var(--color-accent)] text-[var(--color-accent-text)] border-2 border-[var(--color-accent)]";
```
`role="group" aria-label="Record type"`, each button `aria-pressed={recordType === key}`, text-only (no icons in the switcher itself — D-02 says "mirrors FilterBar exactly," and FilterBar's segmented buttons are text-only).

**Field-set subsection header (h3):** icon (`FlaskConical`/`Siren`/`Stethoscope`, `size={24}`, `aria-hidden="true"`) + text, `flex items-center gap-2 text-[20px] font-bold text-[var(--color-ink)]`.

**Submit button:** mirrors `DateRangePicker`'s Apply button classes verbatim (D-06 locked):
```tsx
canSubmit
  ? "min-h-12 self-start rounded-lg bg-[var(--color-accent)] px-6 text-[20px] font-bold text-[var(--color-accent-text)]"
  : "min-h-12 cursor-not-allowed self-start rounded-lg border-2 border-dashed border-[var(--color-ink)] bg-[var(--color-sky)] px-6 text-[20px] font-bold text-[var(--color-ink)]"
```
`aria-disabled={!canSubmit}`. Label reads "Add Lab Result" / "Add Incident" / "Add Procedure" per the active type.

**Confirmation (success):** mirrors `UploadPage`'s success section exactly:
```tsx
<section role="status" aria-label="Add record result"
  className="flex items-start gap-2 rounded-lg border-2 border-[var(--color-ink)] bg-[var(--color-sky)] p-6 text-[var(--color-ink)]">
  <CheckCircle2 aria-hidden="true" size={24} className="mt-0.5 shrink-0" />
  <p className="text-lg text-[var(--color-ink)]">Added 1 {noun}.</p>
</section>
```

**Error:** mirrors `UploadPage`'s error section exactly:
```tsx
<section role="alert" aria-label="Add record notice"
  className="flex items-start gap-2 rounded-lg border-2 border-[var(--color-ink)] bg-[var(--color-sky)] p-6 text-lg text-[var(--color-ink)]">
  <TriangleAlert aria-hidden="true" size={24} className="mt-0.5 shrink-0" />
  <p>
    <span className="font-bold">Something went wrong saving that {noun}.</span>{" "}
    Nothing was added — please try again.
  </p>
</section>
```

**Form reset:** `key={`${recordType}-${resetSeq}`}` on whichever field-set is
mounted; bump `resetSeq` on successful submit (D-03 clear-and-stay) — this
gives both post-submit clearing and silent type-switch discard for free via
React's unmount/remount, no manual clear function needed (RESEARCH Pattern 3).

**SingleDateField:** new component, `mode="single"` `DayPicker` + typed
`YYYY-MM-DD` text input, same 48px day-cell sizing (`rdpSizing` CSS vars) and
`inputClass` as `DateRangePicker`'s existing fields (RESEARCH Pattern 2) —
do NOT import `<DateRangePicker>` directly (Pitfall 2).
