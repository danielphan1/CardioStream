<objective>
Close verification Gap 1 (blocker) in `backend/app/etl.py` and the three same-file warnings the verifier explicitly recommended fixing alongside it (WR-01, WR-03, WR-04 from 01-REVIEW.md).

Gap 1 (CR-01 + WR-02): `_validate_row` accepts any positive float but the derive loop coerces with `int(raw)`. A text-decimal vital like "118.5" (or "inf") passes validation then raises an unhandled ValueError that aborts the ENTIRE file — violating locked D-08 ("one bad cell never blocks the rest of the file"). A native float 129.9 is silently floor-truncated to 129 and classified 'Elevated' when 130 would be 'Stage 1' — violating the project's "derived medical categorizations must be correct" constraint.

Chosen behavior (pinned by this plan, per D-08 + medical-correctness): REJECT non-integer and non-finite vitals with a per-row reason — never round, never truncate. OMRON devices emit integer vitals; a fractional value is format drift or a re-typed cell and must be surfaced, not guessed at.

Gap 2 (DATA-04, real-data seeding) is human-blocked by design (user chose 'skip' at the 01-01 checkpoint) and is NOT addressed by code in this plan — see 01-VERIFICATION.md Human Verification section.

Purpose: Phase 1's D-08 invariant and medical categorization correctness hold on every input the pipeline can encounter; the Phase 5 upload route inherits a transform that cannot 500 on one bad cell.
Output: Fixed `backend/app/etl.py` plus regression tests pinning every fixed behavior.
</objective>
