<objective>
Convert `store/filters.ts` — the zustand store that IS the agent command schema — from single-value `amPm`/`bpCategory` sentinels to the multi-select map shape locked in `15-UI-SPEC.md` §2: `bpCategory: Record<BPCategory, boolean>`, plus two brand-new `pulseCategory`/`timeOfDay` maps, with `amPm` dropped entirely (resolved Option B). Add the v2→v3 localStorage migration chained after the existing v1→v2 migration, following that migration's own governing principle verbatim: never silently reset a caregiver's prior selection on first load after deploy.

Purpose: Every consumer of the filter store — FilterBar, the agent bridge, EmptyState, useStats — is built in the next wave against whatever store action signatures land here. This plan pins those signatures.

Output: A working, migrated, tested store with the final v3 shape and action set.

**STORE ACTION DESIGN (planner decision, pin exactly):** Each of the three category groups gets TWO actions, mirroring the existing `setDataset`/`showOnlyDatasets` pair's two distinct semantics (one single-key toggle, one full-replace):
- `toggleBpCategory(category: BPCategory, on: boolean)` — mutates exactly one key, leaves the rest of the map alone. This is what FilterBar's checkbox `onChange` calls (plan 15-05).
- `setBpCategory(categories: BPCategory[])` — REPLACES the whole map: every key in `categories` becomes `true`, every other key becomes `false` (built from `CLINICAL_ORDER`, not by spreading current state — same "exhaustive, never stale" reasoning `showOnlyDatasets` already uses). This is what the agent bridge calls (plan 15-06) with the full desired selection Claude sent.
- Identical pair for pulse category: `togglePulseCategory(category: PulseCategory, on: boolean)`, `setPulseCategory(categories: PulseCategory[])`.
- Identical pair for time of day: `toggleTimeOfDay(bucket: TimeOfDayBucket, on: boolean)`, `setTimeOfDay(buckets: TimeOfDayBucket[])`.

The `toggle*` actions are UI-only — never voice-reachable (no `AppliedFilters` field maps to "flip one category and leave the rest") — same status as the existing `initFilters` bootstrap action. The `set*` actions ARE voice-reachable (mirror `AppliedFilters.bpCategory`/`pulseCategory`/`timeOfDay` from plan 15-02/15-03 exactly).
</objective>
