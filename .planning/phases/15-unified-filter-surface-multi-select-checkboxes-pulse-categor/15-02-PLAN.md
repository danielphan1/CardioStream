<objective>
Convert the Claude-facing agent wire schema (`backend/app/agent/schemas.py`) so `bp_category` becomes list-typed (matching `ShowOnly.datasets`'s existing list-of-`Literal` precedent verbatim), add new list-typed `pulse_category`/`time_of_day` fields, remove the `am_pm` field and token vocabulary entirely, and add a sibling `*_all: bool` clear-signal flag per group (the mechanism the old `"all"` token used to provide, now that `"all"` is no longer a legal list element). Wire the service layer (`_apply_command`) and the system prompt (`prompt.py`) to match, and propagate the change through every backend agent test file plus the offline eval fixture JSON.

Purpose: This is the wire-contract half of the phase's cross-stack conversion — the frontend's `AppliedFilters` TS type (built in plan 15-03) and store shape (plan 15-04) both mirror whatever lands here exactly.

Output: A working `DashboardCommand`/`AppliedFilters` schema supporting multi-category filter commands and an explicit "clear to all" signal per group, with `am_pm` fully retired.

**PLANNER DECISION (PD-01, documented per orchestrator instruction):** The "clear this filter back to all" mechanism for the now list-typed `bp_category`/`pulse_category`/`time_of_day` fields is a sibling `*_all: bool = False` flag per group (e.g. `bp_category_all: bool = False` alongside `bp_category: list[BPCategoryToken] | None = None`) — RESEARCH Focus Answer 3's recommended option. This mirrors the existing `reset: bool = False` idiom already coexisting with `DashboardCommand`'s optional fields, is a smaller blast radius than overloading `"all"` as a special single-element list value, and keeps `BPCategoryToken`/`PulseCategoryToken`/`TimeOfDayToken` as pure closed vocabularies of real values only. Precedence when both a list AND the matching `_all` flag are present in one command (a possibly-confused model output): the `_all` flag wins — it maps to the empty-list "clear to no restriction" state and the accompanying list value, if any, is ignored. Document this precedence in `_apply_command`'s code comment.
</objective>
