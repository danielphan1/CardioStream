<objective>
Convert `ReadingFilters` (`backend/app/deps.py`) — the shared filter dependency behind `GET /readings` and `GET /stats/summary` — from single-value equality filters to list-typed `IN`-semantics filters for `bp_category`, add a new `pulse_category` list filter (mirrors `bp_category` exactly — the column and its derivation already exist, this only exposes it), and add a brand-new `time_of_day` list filter backed by a query-time-only hour-of-day predicate (no stored column, no ETL change). Remove the `am_pm` query filter entirely (planner decision, documented below) since `time_of_day` replaces it and the frontend will never send `am_pm` again once Phase 15 ships in full.

Purpose: This is the backend foundation every other Phase 15 plan builds on — the frontend, the agent schema, and the wire contract all mirror whatever shape lands here. It has zero dependency on any other Phase 15 plan and unblocks them all.

Output: A working, tested `IN`-clause filter set on `/readings` and `/stats/summary` covering `bp_category` (converted), `pulse_category` (new), and `time_of_day` (new, with correct midnight-wrap handling), with `am_pm` filtering removed.

**PLANNER DECISION (PD-02, documented per orchestrator instruction):** The backend `am_pm` query parameter is REMOVED from `ReadingFilters`, not converted to a list and not kept-but-deprecated. Rationale: Phase 15's resolved Option B drops `amPm` from the frontend store entirely — the frontend will never send `am_pm` again — and `time_of_day` is the functional superset/replacement (finer-grained, same underlying `datetime_` hour). Keeping an unreachable, never-sent filter parameter alongside its own functional replacement is exactly the kind of dead flexibility this codebase's own audit conventions remove (STATE.md's `260913-fdm` entry). The `Reading.am_pm` COLUMN and `ReadingOut.am_pm` response FIELD are UNCHANGED — still ETL-derived, still returned and displayed in the readings table — only the redundant query *filter* is deleted.
</objective>
