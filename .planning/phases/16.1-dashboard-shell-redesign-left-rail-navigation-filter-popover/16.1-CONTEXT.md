# Phase 16.1: Dashboard Shell Redesign — Context

**Gathered:** 2026-09-30
**Status:** Ready for UI contract
**Source:** Direct client session (brainstorming), three reference dashboards supplied as images

<domain>
## Task Boundary

Make the data the primary object on the CardioStream dashboard. Measured in-browser on 2026-09-30 against the running dev server:

| Region | Measured height |
|---|---|
| Header band | 216px |
| Command bar | 80px |
| FilterBar + ShowPanel | **624px** |
| StatsStrip | 588px |
| **The chart** | **450px** |
| Total chrome above the first chart | **1,508px** |

The filter system is larger than the chart it filters, and roughly 1.7 viewport-heights of chrome precede any visualization.

**The governing insight:** the ≥48px target / ≥18px text floor means chrome cannot be made *smaller*. It can only be *relocated* or *removed*. Every decision below follows from that.
</domain>

<decisions>
## Implementation Decisions — LOCKED, do not re-ask

### Shell — left rail + filter popover
Chosen over (a) keeping full-width bands with collapsed filters, and (b) a multi-chart grid.
- 240px fixed left rail holds navigation (Dashboard, Readings, Upload, Add Record) plus the utility controls currently in the header. The 216px horizontal header band goes away as a band.
- Below 1024px the rail becomes a drawer behind a 48px menu button in a slim top bar. It must NOT become a horizontally scrolling band — DESIGN.md's No-Off-Screen Rule forbids it.
- The drawer reuses the filter popover's dismissal mechanics so the app ships ONE modal pattern, not two.
- ReadingsTable becomes its own rail destination rather than living below the chart. Its internals do not change.

### Command bar — unchanged and still prominent
Stays full-width at the top of the content area. It does NOT move into the rail and does NOT collapse. PRODUCT.md requires the text fallback prominent, not hidden, and it is the one component the primary user actually drives.

### Filtering — trigger row + popover
- One row: `[Dates: All]` and `[Filters · N]`, where N counts active non-default filters. Both ≥48px.
- Popover contains Time of Day, BP Category, Pulse Category, and the Show-datasets group.
- Build on GuideOverlay's EXISTING focus-trap / Escape-to-close / return-focus-to-trigger implementation. Do not write a second modal system.
- **Hard requirement:** the D-20 filter-state sentence (`aria-live`, e.g. "All data · All times of day · All categories") stays VISIBLE on the page, never inside the popover. It is how the primary user knows what is applied without opening anything; burying it would break the voice-first path while looking tidier.
- Agent-driven filter changes with the popover closed must still pulse the trigger (reuse `useAgentPulseFlash`) and update the live sentence.
- Chart-view switching LEAVES the filter row and sits directly above the chart — it is a property of the chart, not a filter.

### Vitals — inline strip
Four readouts in one ~90px row (from 588px): label, large number, quiet min–max. Sparkline and status pill are DROPPED — both duplicate the chart directly below at worse fidelity. Chosen over compact-cards-with-sparklines and over a right-hand vertical rail.

### Color — teal owns chrome only
Client chose a teal accent after being shown the full blast radius, then chose the narrowest scoping of it.
- `--color-brass` → `#0E8C74` teal. Scope: selected rail item, selected date and time-of-day, Send, Apply. Chrome only.
- The six AHA BP-category colors are **UNCHANGED**. The three overlay colors are **UNCHANGED**.
- Category chips mark selection with a ~12% tint of their own hue plus a 2px border in that hue — **never teal**. This avoids painting teal over the green "Normal" chip, the one combination in this palette that reads as a bug.
- `--line-diastolic` (`#1F7A6C`) must LEAVE the teal family so a chart line cannot be confused with the accent.
- `--color-signal` (`#0F6E86`) is a teal-blue and now collides with the accent. DESIGN.md explicitly forbids focus and accent collapsing into one color, so the focus ring must move too. Candidate the client has seen: demote brass (`#8A5A1E`) to the focus ring — already contrast-verified in both themes, and warm against a cool accent.
</decisions>

<constraints>
## Non-negotiable

From CLAUDE.md and PRODUCT.md. The primary user is a C4 quadriplegic with limited/no hand mobility who cannot reliably use a pointer.

- ≥48px interactive targets; ≥18px body text; high contrast; full keyboard navigability.
- No hover-only, drag, or precise-pointing interactions anywhere.
- Every primary action reachable by voice.
- The reference images are mouse-first dashboards built on ~11–13px labels and small hit areas. Take their INTENT (visual dominance, quiet chrome); do not copy their metrics.
- `frontend/src/tests/contrast.test.ts` currently passes 38 assertions and must keep passing. Every new or moved color needs its pair added there.
- Only 400 and 700 font weights exist (Atkinson Hyperlegible static files). A third weight would be synthesized — a regression.
</constraints>

<specifics>
## Specific references and known hazards

**Reference dashboards supplied by the client (3 images):** a teal/green medical SaaS dashboard with a dark rail; a white/green clinical dashboard with a KPI row, large area chart and a right-hand vitals column; and a Zoho hospital-operations dashboard with a dark rail, a row of compact filter dropdowns, a six-tile KPI strip and a three-up chart grid. Common thread: left rail, filters collapsed to compact triggers, KPI tiles small, charts dominant, one saturated accent used sparingly.

**Hazards the spec must close:**

1. **Diastolic's replacement hue must be derived, not picked.** Systolic and diastolic sit at only 1.89:1 luminance separation today, which is why pulse draws dashed (see `CombinedTimeline` comments). Check the replacement in greyscale, not just in color.
2. **The rail narrows the chart container by 240px**, giving `categoryBarRightMargin` a new narrowest case. Measured in-browser 2026-09-30: `estimateChipWidth` currently over-estimates the longest label by 72px (Atkinson renders it at 294.9px against a 367px estimate; the factor actually needed is 0.498 vs the 0.62 in use), so there is headroom — but `chartData.test.ts` hardcodes 383/295/40 and must be re-checked against the new container width rather than assumed.
3. **Popover + voice interaction** — see the D-20 requirement above.
</specifics>
