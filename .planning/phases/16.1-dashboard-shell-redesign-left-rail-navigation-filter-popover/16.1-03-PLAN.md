## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| keyboard/switch-access input → focus management | `useDismissable` decides what receives focus on open and close. A trap here would lock the primary user out of the mic, which is his only reliable input — so "no trap" is a safety property of this boundary, not a style choice (D-03/D-04). |
| `/health` response → ShellNav rendering | `demoMode` is read from the already-authenticated `/health` payload to suppress the two write destinations. It is a UI affordance only; the backend still owns write authorisation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16.1-08 | Elevation of Privilege | ShellNav's `demoMode` suppression of Upload / Add Record | accept | Hiding the destinations is a UX affordance reproducing today's `Header.tsx` behaviour exactly; the real gate is the backend's guest-demo write rejection shipped in Phase 19 and untouched here. ShellNav adds no new write path. |
| T-16.1-09 | Denial of Service | `useDismissable`'s focus and Escape handling | mitigate | No focus trap is introduced (grep-gated in the acceptance criteria) and the window-level Escape listener is removed on close and unmount, so no surface can strand keyboard focus or leave a dangling global handler |
| T-16.1-10 | Tampering | `useMediaQuery` reading `window.matchMedia` | accept | A media query string is a developer-supplied literal, never user input; the guard returns `false` rather than throwing when the API is absent |
| T-16.1-11 | Spoofing | `document.getElementById(triggerId)?.focus()` | accept | `triggerId` is a developer-supplied literal from a fixed set of three ids; a missing element is handled by optional chaining, matching GuideOverlay's shipped behaviour |
| T-16.1-12 | Tampering | npm/pip/cargo installs | mitigate | Not applicable: no dependency is added (UI-SPEC §10) — no package-legitimacy checkpoint required |
