<objective>
Collapse the 624px filter block into a trigger row plus a disclosure (UI-SPEC §5.3/§5.5) and relocate the three live state lines into the always-visible single-region block below it (§5.4), mounting everything through `AppShell` so the <768px panels land as siblings of `<main>` exactly as §5.0's structure table requires.

Purpose: This is the change that makes the filter system smaller than the chart it filters — the client's actual request. Two parts are load-bearing and must not be traded away for tidiness: the live state block stays on the page because the primary user cannot see a popover he has not opened, and the agent pulse is consumed in the always-rendered trigger so an agent-applied change is perceivable with the popover closed. The controls themselves are **moved, not rewritten**, which is also what keeps the existing group tests alive.

Output: a two-trigger row with a count badge; one `FilterSurface` serving both the anchored ≥768px popover and the <768px full-viewport panel; `FilterStateBlock` mounted in the content column; the old full-width filter band cluster gone.

Task order is a correctness constraint, not a preference. `FilterBar.tsx:33-35` declares `latestReading` as a **required** prop, so the task that renders `<FilterBar />` propless inside `FilterSurface` must be the task that removes it — otherwise its own `npx tsc -b --noEmit` gate fails with TS2741. Removing it earlier would ship a commit with the D-20 sentence absent from the page. Both constraints are satisfied by doing the strip, the `FilterStateBlock` mount and `FilterSurface` **together in task 2**, which leaves task 3 as the trigger row plus the cluster wiring.
</objective>
