## Decisions Made

1. **One commit, not two.** The plan's `<verification>` block states `git show --stat HEAD` lists 19 files and uses `git show HEAD~1:frontend/src/index.css` as the hex-diff baseline — both only hold if the whole rename is one commit. Independently: a Task-1-only commit would declare `--color-accent` in `index.css` while 17 consumers still referenced the then-undefined `var(--color-brass)`, so every accent fill, border and ring in the app would render transparent at that commit. UI-SPEC §4.2 says "its own commit" (singular). The task-per-commit default was overridden to keep the commit atomic and non-broken.
2. **`LoginGate.tsx:160` keeps the word brass.** `"the old 50%-opacity fade took brass-on-deck from 5.9:1 to roughly 2.6:1"` is a measured historical figure about `#8A5A1E` on deck, recorded as the reason the dimmed-opacity disabled state was rejected. Renaming it to `accent-on-deck` would make the 5.9:1 number false as soon as 16.1-02 sets the accent to `#0D826C`. The plan's action text explicitly excludes "comments that describe the colour brass as a hue in a historical note" from the rewording sweep. Flagged here so 16.1-02's reviewer sees it was deliberate, not a missed occurrence.
3. **`npm ci` in the worktree.** `frontend/node_modules` did not exist in the fresh worktree, so the first baseline run failed with `ERR_MODULE_NOT_FOUND: Cannot find package 'vite'`. Restored from the committed `package-lock.json`. No package added, removed, or version-changed — `package.json` and `package-lock.json` are unmodified and `node_modules` is gitignored, so nothing entered the commit.

## Deviations from Plan

### Deviation 1 — commit granularity (not a code change)

**[Rule 3 — Blocking / plan-internal consistency] Two tasks committed as one**

- **Found during:** end of Task 1, before committing
- **Issue:** Committing Task 1 alone would (a) make the plan's own `<verification>` assertion `git show --stat HEAD` lists 19 files unsatisfiable, and (b) land a commit where `index.css` defines `--color-accent` but 17 files still read `var(--color-brass)` — i.e. a commit that renders every accent surface as transparent. The "no commit lands red" gate and the plan's "the rendered app is pixel-identical" success criterion both argue against it.
- **Fix:** Task 1's edits were verified in full (hex-multiset gate clean, `contrast.test.ts` 38 passed) *before* Task 2's edits were made, then both were staged and committed together as `e43986a`.
- **Files modified:** none beyond the plan's 19.
