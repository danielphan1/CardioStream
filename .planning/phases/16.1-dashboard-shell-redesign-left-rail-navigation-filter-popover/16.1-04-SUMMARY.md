# Phase 16.1 Plan 04: Filter Layer Pure + Presentational Pieces Summary

Extracted the D-20 filter sentence into a pure `buildFilterSentence`, added the group-counting `activeFilterCount`, re-treated the category chips from solid clinical fills to a 12% own-hue tint with a hue-matched border and an always-present dot, and created the single-polite-live-region `FilterStateBlock` — built but not yet mounted.

## What Was Built

**Task 1 — `buildFilterSentence` + `activeFilterCount`** (`5b0d522`)

`FilterBar.tsx`'s inline sentence block moved **verbatim** into `lib/showSentence.ts`. FilterBar now calls the extracted function and renders the result in the same `<p aria-live="polite">` at the same position, so the component stays behaviour-neutral and `FilterBar.test.tsx` passed unmodified throughout.

`activeFilterCount(state)` counts how many of four groups differ from their shipped default. Implemented as one generic `differsFromDefault(current, defaults)` helper driven off each `DEFAULT_*` map's own keys, called four times and summed. That one helper is what makes the dataset case correct for free: because the datasets default is a specific map (`{blood_pressure: true, pulse: true, …}`) rather than "all false", turning `blood_pressure` **off** counts exactly like turning `labs` **on**. The four `DEFAULT_*` maps gained `export` in `store/filters.ts`; nothing else in the store changed (state shape, persistence and action set are untouched per §8).

**Task 2 — chip re-treatment per §4.4** (`b3773ea`)

Both the BP and Pulse chip groups now mark selection with three simultaneous changes — a 12% tint of the category's own hue as fill, a 2px border in that same hue, and the native tick — plus a 12px category dot rendered in **both** rest and selected states so clinical identity never disappears. The dot markup is reused from `StatsStrip.tsx`'s legend dot so the two surfaces cannot drift. The 3px ink `box-shadow` ring is removed from both groups, leaving `:focus-visible`'s outline as the only ring on the control. Checkbox `accentColor` is `var(--color-depth)`, **not** the accent — the teal-over-the-green-Normal-chip trap. This is the first consumer of plan 02's tint accessors.

**Task 3 — `FilterStateBlock`** (`5e31eda`)

One wrapper `<div>` owns the single polite live region; the three `<p>` elements carry no live attributes, no `aria-atomic` and no `role`. The region is left non-atomic and is never assertive. Created but **not mounted** — plan 07 mounts it, applies the outer spacing (8px below the trigger row, 24px above the vitals strip) and strips ShowPanel's two sentence paragraphs. Nothing that currently renders the D-20 sentence was removed, so the commit is behaviour-neutral.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] My own test expectation for the day-preset anchor was wrong**
- **Found during:** Task 1
- **Issue:** I first asserted `"Last 30 days to June 13, 2025 · …"`. The test failed: the real output is `"Last 30 days · to June 13, 2025 · …"`.
- **Root cause:** the anchor is pushed as its **own** `sentenceParts` entry, so it joins with `" · "`, not a space. FilterBar did exactly this before the extraction, so the extracted output is byte-identical and the **code was correct** — only my expectation was wrong.
- **Fix:** corrected the expectation and left a comment warning against "fixing" it to the space form, which would be precisely the reword §5.4 forbids.
- **Files modified:** `frontend/src/lib/showSentence.test.ts`
- **Commit:** `5b0d522`

**2. [Rule 3 - Blocking] Explanatory comments tripped Task 3's acceptance greps**
- **Found during:** Task 3
- **Issue:** The plan asks for comments explaining the one-region rationale, *and* asserts `grep -c "aria-live"` = 1, `grep -c "assertive"` = 0, `grep -c 'aria-atomic="true"'` = 0 on the same file. My first draft quoted those attribute literals while explaining them, so the counts came out 3 / 1 / 1.
- **Fix:** reworded the header comment to state the same facts in prose ("their own polite live attribute", "left non-atomic", "never urgent/interrupting") without the literal attribute strings, and added a line telling the next editor why the literals must stay out of the comments. All reasoning the plan asked for is preserved.
- **Files modified:** `frontend/src/components/FilterStateBlock.tsx`
- **Commit:** `5e31eda`

### Deliberate Choices Worth Flagging

**`NOTE_COPY` is duplicated, not imported.** The plan allowed either "move that constant here or re-declare it with identical text". I re-declared it: `ShowPanel.tsx` is **not** in this plan's `files_modified`, and exporting the constant from it would have meant touching a file outside my declared set during parallel execution with plan 05. The duplicate carries a comment naming the other copy and pointing at plan 07, which strips ShowPanel's paragraphs and can collapse the duplication then. Until that happens, the string exists in two places — if plan 07 does not collapse it, this is a real (small) drift risk on a user-visible string.

**`showSentence.ts` is no longer import-pure.** It now imports the store's `DEFAULT_*` maps, which transitively pulls in zustand, breaking the file's stated no-impure-imports invariant. This is required by §5.3 ("do not re-type the defaults") and is safe because every vitest suite runs under jsdom (`vite.config.ts` `test.environment: 'jsdom'`) and the store's `localStorage` access is lazy, never at module load. The file header records the exception and the escape hatch: if the invariant is ever needed back, move the four maps into a `lib/filterDefaults.ts` that both modules import — never duplicate them.
