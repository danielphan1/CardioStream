## Accomplishments

- **Accent is now teal in both themes** — `#0D826C` / `#33C1A6`. White-on-accent measures **4.74:1**, clearing the 4.5:1 WCAG 1.4.3 normal-text floor, which is what makes the 18px/400 Filters count badge in plan 16.1-07 legal. The dark value holds luminance parity with the brass it replaces (Y = 0.4160 vs 0.4162), so perceived accent weight is unchanged at night.
- **Focus ring is brass** — `#8A5A1E` / `#D9A356`, 135 degrees of hue from the accent, so focus and active state can never be confused.
- **Closed a pre-existing sub-floor focus gap** on the Command Bar's always-dark panel. The light ring measured **2.90:1** there, under the 3:1 non-text floor. New non-inverting `--color-signal-on-panel` + `[data-surface="panel"] :focus-visible` override measures **7.60:1** light / **8.81:1** dark.
- **Violet `--line-diastolic`** — raises dark systolic-vs-diastolic greyscale separation from **1.12:1 to 2.24:1**, which was the palette's worst number (two solid chart series effectively identical to a greyscale or colour-blind viewer).
- **14 precomputed tint tokens** (7 per theme) plus `categoryTint()` / `pulseCategoryTint()`, so plan 16.1-04's selected-chip treatment never needs a hex.
- **Gate at exactly 92 assertions**; suite 39 files / 618 tests (558 baseline − 38 + 92 contrast + 6 new palette cases).

## Verification Beyond the Green Suite

The plan called out the blind spot explicitly: `contrast.test.ts` holds its hexes as **independent literals and never reads `index.css`**, so a value changed in one file without the other passes silently. This was confirmed live — after Task 1 the full suite still reported **558 passed** with the test file holding entirely stale hexes. A green suite proves nothing here, so three independent checks were run:

1. **Per-theme literal comparison.** Extracted all 56 unique hexes from `contrast.test.ts`; 44 are present in `index.css` and 12 are absent. The 12 absent are exactly the derived `*Dimmed*` blends (`0.85 x line + 0.15 x background` opacity simulations), which are not CSS tokens — correct by design. The remaining 44 were then checked **per theme** by printing the `:root` and `.dark` blocks separately, because mere presence somewhere in the file would hide a light/dark swap. Every value matches its theme.
2. **All 18 measured ratios match the UI-SPEC's published figures exactly** — including the ranges: `depth`-on-tint 12.82–13.65 light / 12.99–14.26 dark, category-vs-mist 3.93–8.50 / 5.00–8.98, dot-on-tint 3.79–7.72 / 4.94–8.08. Also confirmed the retired light ring measured 2.90:1 on panel and that `sys/pulse` is unchanged at 1.89:1 / 1.14:1. The four new `lineDiastolicDimmed*` blends were independently recomputed from the blend formula and match to the byte. No spec number needed correcting.
3. **Token existence, not just token shape.** `palette.test.ts` only regex-matches the returned string, so a typo like `--cat-stage-1-tint` would pass every test while resolving to nothing in CSS. All 7 tint tokens referenced in `palette.ts` were confirmed declared in `index.css`.

Additional checks: all four retired literals (UI-SPEC §7.3) are gone — 0 occurrences in `frontend/src` and 0 repo-wide outside `.planning/` (where they are legitimately cited as historical record). `contrast.test.ts` is the **only** test file in the codebase containing hex literals, so no other stale mirror of the palette exists.
