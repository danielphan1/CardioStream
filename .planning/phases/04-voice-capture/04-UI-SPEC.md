# Phase 4 — UI Design Contract

> Visual and interaction contract for the voice layer. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Theme in one sentence: **the existing calm coastal command bar gains a voice — one large mic, a from-across-the-room 3-state indicator, and a live green transcript, all inside the bar Chris already knows, using only the Phase 2 tokens.**
>
> Governing accessibility floor (CLAUDE.md, non-negotiable): all interactive targets ≥48px, body text ≥18px, high contrast everywhere information lives, keyboard navigable with visible focus, no drag / hover-only / precision interactions. Every state is encoded by **color + word + icon/motion together — never color alone** (D-07). Motion honors `prefers-reduced-motion` with a static fallback (D-09).
>
> **Reuse mandate:** this phase adds ZERO new design tokens, ZERO new colors, ZERO new fonts. Every value below already exists in `frontend/src/index.css` and `02-UI-SPEC.md`. The voice layer consumes `var(--…)` and never introduces a hex value. It also introduces no new component surface beyond a mic button + indicator/transcript inside the existing `CommandBar.tsx` (D-06).

Registry safety gate is therefore not applicable (see Registry Safety).

## Spacing Scale

Reuses the Phase 2 8-point scale verbatim (all multiples of 4). No new values.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Icon-to-word gap inside a state indicator |
| sm | 8px | Gap between mic icon and its label; gap between spinner and "WORKING…" |
| md | 16px | Gap between the mic button and the text input inside the bar form (`gap-3` = 12px is the existing bar gap; keep it) |
| lg | 24px | Vertical breathing above the transcript region if needed |
| xl | 32px | (unchanged page rhythm — not touched this phase) |
| 2xl | 48px | **Minimum interactive target** — the mic button is ≥48px (`min-h-12` + `min-w-12`), matching the existing Send button and every FilterBar control |
| 3xl | 64px | (unchanged) |

Exceptions / phase-specific notes:
- **Mic button target:** the existing bar controls use `min-h-12` (48px). The mic is the primary voice CTA and the one control a caregiver taps to open the session — it must be at least `min-h-12 min-w-12` (48×48px). A larger touch target (e.g. `h-14 w-14` = 56px) is permitted and encouraged for distance/wheelchair reach (default: `min-h-12 min-w-12`, upsize allowed within accessibility budget — this is the "exact mic-button placement/size" left to the planner in CONTEXT §Claude's Discretion).
- **Existing bar gap:** CommandBar's form already uses `gap-3` (12px). The mic button joins the same flex row; keep `gap-3` — do not introduce a new gap value.

## Typography

Reuses the Phase 2 4-size / 2-weight scale (Atkinson ships only 400/700). No new sizes.

| Role | Size | Weight | Line Height | Used for in this phase |
|------|------|--------|-------------|------------------------|
| Body | 18px | 400 | 1.5 | Live interim transcript text; the armed hint `LISTENING — say "dashboard…"`; the D-14 paused copy; confirmation text (reused from Phase 3) |
| Label | 20px | 700 | 1.2 | The state WORD in the indicator (`LISTENING` / `WORKING…` / `TAP TO SPEAK` / `Voice paused`) — bumped to Label weight so it reads from across the room; mic button accessible label |
| Heading | 24px | 700 | 1.2 | (not introduced by voice) |
| Display | 32px | 700 | 1.2 | (not introduced by voice) |

Rules:
- The **state word** is the load-bearing signal for distance legibility (D-07: "legible from across the room / a wheelchair"). Render it at **20px weight 700** (Label role). A larger size (up to 24px Heading) is permitted for the state word only, if the planner judges distance legibility needs it — note as `(default 20px, upsize to 24px allowed)`.
- The **live transcript** renders at 18px body weight 400 (matches the existing bar text and reply region) so the transcript reads as speech-in-progress, not a headline.
- No new size or weight is introduced. 18px stays the floor; nothing readable renders smaller.

## Color

**No new colors.** Every value below is an existing CSS custom property in `frontend/src/index.css`, flips automatically between the two themes (light "airy nautical" default / dark "night sea", `.dark` manual toggle), and was contrast-computed in `02-UI-SPEC.md`. The three voice states map onto existing tokens and are **always** paired with a word + icon/motion so meaning never depends on color (D-07, accessibility non-negotiable).

### 60/30/10 role (unchanged from Phase 2)

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--color-foam)` (`#F2F7F5` light / `#0B1626` dark) | Page background; the mic-button surface when idle/armed |
| Secondary (30%) | `var(--color-sky)` (`#E2EDF2` / `#13233A`) | The command-bar band the whole indicator lives on |
| Ink (text) | `var(--color-ink)` (`#14213D` / `#E8F1EF`) | All text, icons, borders, including the TAP TO SPEAK mic glyph + word |
| Accent (10%) | `var(--color-accent)` (`#14213D` / `#8FC1D4`) | Reserved fills only — see reserved list below |
| Focus ring | `var(--color-focus)` (`#1D4E89` / `#8FC1D4`) | 3px `:focus-visible` ring + 2px offset on the mic button (global rule already in index.css) |
| Destructive | none this phase | Voice capture has no destructive actions (see Copywriting) |

### The three voice states → existing tokens (D-07)

Each state is a **triad: color + word + icon/motion**. Color alone never carries meaning.

| State (D-07/D-11) | Color token | Word (20px/700) | Icon | Motion (motion-safe) | Reduced-motion fallback (D-09) |
|-------------------|-------------|-----------------|------|----------------------|-------------------------------|
| 🟢 LISTENING (armed) | `var(--cat-normal)` sea green (`#2F7D5C` / `#63C68F`) | `LISTENING — say "dashboard…"` (armed hint, D-10) | `Mic` (lucide) | `motion-safe:animate-pulse` ring | static solid 3px ring in `--cat-normal` (no pulse) |
| 🟢 LISTENING (triggered) | `var(--cat-normal)` sea green | live interim transcript (word stripped) rendered **in green** (D-10/D-11) | `Mic` | `motion-safe:animate-pulse` ring | static solid ring |
| 🟠 WORKING… (processing) | `var(--cat-elevated)` deep amber (`#8F6A00` / `#E0B84E`) | `WORKING…` | spinner glyph (reuse existing CommandBar border-spinner, or `Loader2`) | `motion-safe:animate-spin` | static spinner glyph / static amber ring (no spin) |
| ⚪ TAP TO SPEAK (stopped/idle) | neutral `var(--color-ink)` on `var(--color-foam)` | `TAP TO SPEAK` | `Mic` | none | none (already static) |
| ⚪ Voice paused (hard failure, D-14) | neutral `var(--color-ink)` | `Voice paused — tap to resume` | `MicOff` | none | none (already static) |

Rationale for reusing `--cat-normal` / `--cat-elevated` rather than new greens/ambers: these two clinical tokens are already contrast-computed (green fill vs foam 4.61:1 light / 8.65:1 dark; amber fill vs foam 4.59:1 / 9.62:1 — from 02-UI-SPEC.md), already flip with the theme, and green=listening / amber=working reads as a natural traffic-light semantic without importing a new palette. The voice states use these as **ring/border/glyph colors and the transcript text color**, not as large filled surfaces, so the graphics 3:1 floor governs the rings and the 4.5:1 text floor governs the green transcript text (both are cleared by the computed ratios above).

**Accent (filled navy/sky) reserved for exactly** (unchanged from Phase 2, plus one addition): active date-preset button, active AM/PM segment, active category chip, "Show all data", "Show 20 more", tooltip Close, calendar selected-day, the Send button, **and the working-state bar ring already present in CommandBar** (`ring-2 ring-[var(--color-accent)]`). The mic button itself is NOT an accent-filled control by default — it is an ink-bordered `--color-sky`/`--color-foam` card matching the inactive-control convention, EXCEPT its color/icon swaps per the state table above. It may adopt the green LISTENING ring while a session is open (that green is the state signal, not an accent fill).

The whole command bar transforms to signal state (D-06) — the existing working-state ring (`ring-2 ring-[var(--color-accent)]`) is retained for WORKING…; the armed/listening state adds a green ring. No separate banner or orb (D-06).

## Copywriting Contract

Voice: calm, first-person-neutral, sentence case, no medical interpretation ever, no exclamation marks. Verbatim strings come from CONTEXT D-10/D-11/D-14 and §Specific Ideas — use them exactly. WAKE_WORD is a named constant (`WAKE_WORD`, default `"dashboard"`, D-04) — copy that embeds the word must interpolate the constant, not hard-code "dashboard", so a UAT word swap changes one place.

| Element | Copy |
|---------|------|
| Primary CTA (mic button, armed action) | The mic button. Accessible name via `aria-label`, state-dependent (never placeholder-derived): `"Start voice control"` when stopped/idle; `"Stop voice control"` when a session is open. Visible glyph is the lucide `Mic` / `MicOff`; no visible text label required on the button itself, but the aria-label is mandatory (mirrors the Phase 3 "accessible name is a real aria-label, never the placeholder" rule). |
| Armed hint (armed, untriggered — D-10) | `LISTENING — say "dashboard…"` (with `"dashboard"` interpolated from `WAKE_WORD`). Shown while listening but before the trigger word fires; the transcript region shows ONLY this hint, never room speech (D-10). |
| Triggered streaming (D-10/D-11) | Live interim transcript of the captured command **only**, trigger word stripped, rendered in green (`var(--cat-normal)`). Example (endorsed verbatim, CONTEXT §Specifics): `"show blood pressure last 30…"` streaming as Chris speaks. |
| Processing (D-11) | `WORKING…` (amber, spinner) — matches the existing Phase 3 Working… state wording; the voice path reuses the same working indicator. |
| Confirmation (done — D-11) | Reuses Phase 3 `composeConfirmation()` verbatim; the confirmation text **replaces** the transcript in the same spot (one place, one thing at a time). Example: `"Showing blood pressure, last 30 days"`. No new copy — do not author a voice-specific confirmation. |
| Empty state | Not applicable to the voice layer — the dashboard empty state ("No readings match these filters" / "Show all data") is owned by Phase 2 and unchanged. Voice produces commands that reuse it; it authors no empty state of its own. |
| Error state — unrecognized/ambiguous voice command | Reuses the Phase 3 CommandBar failure copy verbatim (VOICE-07, already enforced): `unclear` → the existing friendly "didn't catch that" reply; 429 → `"One moment — a lot of commands at once. Try again in a few seconds."`; offline → `"Couldn't reach the assistant. The buttons below still work. Try: 'show my pulse'."`. Raw error strings/status codes NEVER render (04-RESEARCH.md §Security V7). |
| Error state — hard voice failure (D-14) | `Voice paused — tap to resume` (with a `MicOff` glyph). Shown on unrecoverable failure only: mic permission revoked/denied (`not-allowed`/`service-not-allowed`), no mic hardware, offline, or restart-loop exhaustion (04-RESEARCH.md Pattern 2). The text input box stays fully usable underneath (VOICE-08 fallback) — the bar never traps Chris in a dead voice state. |
| Destructive confirmation | none — voice capture has no destructive actions. Opening/closing a listening session and issuing view commands are all non-destructive and reversible (say another command, or tap the mic to stop). No confirmation dialogs anywhere in this phase. |

First-run permission-prompt copy is left to the planner (CONTEXT §Claude's Discretion) — it must be calm, non-technical, and explain that the browser will ask to use the microphone once. It must not block the text-input fallback.

## Layout & Interaction Contract

**No restructuring of the CommandBar** (D-06). The mic button + 3-state indicator + live transcript all live INSIDE the existing `CommandBar` section (`frontend/src/components/CommandBar.tsx`), which already sits in `App.tsx` between the Header and the dashboard content. The voice layer extends the existing state machine (`idle`/`working`/`confirmed`/`clarify`/`error`) with voice sub-states; it does not add a second component surface.

Bar lifecycle (endorsed verbatim, CONTEXT §Specifics + D-11) — one place, one thing at a time:

1. **Stopped/idle:** `⚪ TAP TO SPEAK` + `Mic` glyph. Text input fully usable. Caregiver taps mic (satisfies the Web Speech user-gesture requirement, D-01).
2. **Armed:** `🟢 LISTENING — say "dashboard…"` + pulsing green ring (static ring under reduced motion). Transcript region shows only the hint; room speech is ignored and never rendered (D-02/D-10).
3. **Triggered:** `🟢` + live interim transcript in green, word stripped, streaming as Chris speaks. A pause (recognizer final result) ends the command (D-03).
4. **Processing:** `🟠 WORKING…` + spinner (static under reduced motion). Reuses the existing bar working ring `ring-2 ring-[var(--color-accent)]`.
5. **Done:** confirmation text REPLACES the transcript in the same spot; charts switch; the session returns to armed LISTENING (explicit stop only — no inactivity timeout, D-13). Caregiver taps mic again to stop.
6. **Hard failure (any point):** `⚪ Voice paused — tap to resume` + `MicOff`; text input stays usable (D-14).

Placement inside the bar form: the mic button joins the existing `flex flex-wrap items-center gap-3` row alongside the text input and Send button (the exact left/right placement within the row is planner discretion, subject to the ≥48px + tab-order rules). The indicator/transcript render in the existing region below the form (where the Working… and reply `aria-live` regions already live), so voice reuses the one announced spot.

Motion (D-09): pulse and spin are gated behind `motion-safe:` (Tailwind), exactly like the FilterBar D-08 precedent (`motion-safe:animate-pulse` + static `ring-2` fallback). Under `prefers-reduced-motion` the pulse collapses to a solid green ring and the spinner to a static glyph — the color+word+icon triad still fully distinguishes every state without motion.

Accessibility & keyboard:
- Mic button is a real `<button>` with a state-dependent `aria-label`, ≥48px, and the global 3px `:focus-visible` ring.
- State transitions announce through the existing `aria-live="polite"` region (already in CommandBar for replies). The word (`LISTENING`/`WORKING…`/etc.) is the announced text; icons are `aria-hidden` visual reinforcement (matches the existing MARKER pattern).
- No hover-only, drag, or precise-pointing interaction is introduced. The mic is a single large tap target; every voice-reachable action is also reachable by the manual FilterBar controls and the text input (VOICE-08 / ACC-03 fallback).
- Tab order: the mic button takes its place in the bar's tab sequence (input → mic → Send, or mic → input → Send per planner placement); it must be keyboard-activatable (Enter/Space) so a keyboard user can open a session too.

Lockstep coverage (VOICE-05 / ACC-03): the voice layer authors no new command vocabulary — it feeds the Phase 3 `/agent` schema unchanged (D-15). The parity guarantee (every manual FilterBar filter is voice-reachable) is enforced by the enumeration test in 04-RESEARCH.md §Validation Architecture, not by UI copy — but the design contract records the intent: **anything a caregiver can do with the FilterBar controls above, Chris can do by voice**, so the two surfaces stay one system.
