<objective>
Build the pure, DOM-free foundation of the voice layer: the wake-word/stripping logic, browser-capability + iOS detection, recognizer-error classification, and restart backoff (all in `lib/voice.ts`), plus the injectable `FakeRecognition` test double, ambient `SpeechRecognition` TypeScript declarations, and the VOICE-05/ACC-03 lockstep parity test.

Purpose: isolate every unit-testable voice concern away from the untestable recognizer lifecycle, and prove no manual filter is voice-unreachable before any UI exists.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| spoken/room speech → recognizer transcript | Untrusted audio becomes a string; wake-word gating (this plan's `extractCommand`) is the first filter that keeps non-commands off the network entirely (D-02) |
| transcript string → /agent | Untrusted text crosses to the backend; already bounded server-side (`AgentRequest.text` max_length 500) and parsed only via structured-outputs Pydantic (Phase 3) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | `extractCommand` → /agent string | mitigate | Voice emits a plain string only; never constructs `AppliedFilters` client-side. Server Pydantic structured-outputs validation (Phase 3) is the authority; closed unions reject anything off-vocabulary. |
| T-04-04 | Info Disclosure | logs / test output | mitigate | Pure helpers never `console.log` the transcript; tests assert on return values, not by printing captured speech (privacy / SEC-03). |
| T-04-SC | Tampering (supply chain) | npm installs | accept | Recommended path adds ZERO runtime packages (native `webkitSpeechRecognition` + reuse). No `react-speech-recognition`/`regenerator-runtime` installed. If a future wrapper fallback is chosen, a blocking `checkpoint:human-verify` per 04-RESEARCH §Package Legitimacy Audit is required before install. |
</threat_model>
