<objective>
Build the one new visible surface this phase adds: a persistent, non-dismissible "assistant unavailable" indicator, proactively checked on page load and polled thereafter, reading from a single shared store field. This plan defines the wire contract (types.ts/client.ts), the store (agentStatus.ts), the poll (useHealth.ts), and the component (AgentStatusBanner.tsx) — everything needed for LIVE-02 and LIVE-03 to be independently true and testable, ahead of Plan 03's reactive D-07 wiring into CommandBar/useVoiceCommand.

Purpose: LIVE-02 (calm, non-alarming, persistent "unavailable" state distinct from "didn't catch that") and LIVE-03 (proactive page-load check, not just reactive-after-failure) both resolve here, using the `kind`/`agent_reachable` wire contract Plan 01 defines on the backend. Per D-10, `AgentStatusBanner` is ONE component with no voice-vs-text variant or prop — it reads a single store field regardless of which path (mic or keyboard) produced the command that last touched it, so there is nothing to keep in sync between two presentations.
Output: `frontend/src/store/agentStatus.ts`, `frontend/src/hooks/useHealth.ts`, `frontend/src/components/AgentStatusBanner.tsx` (all new), plus `types.ts`/`client.ts`/`lib/copy.ts`/`App.tsx` extensions — mounted and tested end to end.
</objective>

## Trust Boundaries

| Boundary | Description |
