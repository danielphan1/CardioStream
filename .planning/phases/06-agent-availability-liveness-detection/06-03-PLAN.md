<objective>
Close the switch-exhaustiveness gap RESEARCH Pitfall 1 identified: `CommandBar.tsx`'s `onSuccess` switch and `useVoiceCommand.ts`'s `handleSuccess` switch both have no compiler-enforced exhaustiveness over `AgentReply.kind`, so Plan 02's newly wire-typed `"unavailable"` value would otherwise fall through silently at runtime with no test catching it. This plan adds the 5th case to both switches AND wires D-07's reactive instant-clear/instant-set behavior — the moment either consumer receives ANY real `/agent` reply, it reports that outcome to the shared `agentStatus` store built in Plan 02, so the banner reacts faster than the next ~60s poll tick.

Purpose: completes LIVE-01's frontend consumption half (the backend already emits `kind="unavailable"` correctly per Plan 01) and delivers D-07 (reactive clear/set) end to end.
Output: both switches handle all 5 `AgentReply.kind` values; both call sites report every real outcome into `store/agentStatus.ts`; regression tests pin both behaviors so a future 6th kind can't repeat this gap silently.
</objective>
