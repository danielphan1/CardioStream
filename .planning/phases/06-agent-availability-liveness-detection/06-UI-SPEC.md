# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase adds exactly one new visible surface: a persistent, non-dismissible
"assistant unavailable" indicator (D-09/D-10/D-11 in `06-CONTEXT.md`). It does
**not** introduce a new visual language — the project already has a locked,
comprehensively documented design system (`frontend/src/index.css`, header
comment: "Design-token system — 02-UI-SPEC.md locked palette"). Every value
below is sourced from that existing system, not invented fresh. No shadcn
gate question was asked of the user (see Design System note) because this is
a continuation phase on an already-shipped, deliberately hand-rolled Tailwind
system, not a greenfield init.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (shadcn not used — see note) |
| Preset | not applicable |
| Component library | none — hand-rolled Tailwind v4 components over CSS custom properties (`frontend/src/index.css`) |
| Icon library | lucide-react (already a project dependency, v1.24.0) |
| Font | Atkinson Hyperlegible (`@fontsource/atkinson-hyperlegible`), 18px body floor, 1.5 line-height (ACC-01, already global in `index.css`) |

**Why no shadcn gate was raised:** `components.json` does not exist and the
stack is React/Vite, which would normally trigger the shadcn init gate. It is
skipped here because the project already has an established, intentional,
non-shadcn design system: `frontend/src/index.css` declares a locked color
token set explicitly labeled "later plans consume `var(--...)` and never
invent color values," and every existing component (`Header.tsx`,
`CommandBar.tsx`, `FilterBar.tsx`) already follows one consistent hand-rolled
convention (2px ink borders, `rounded-lg`, `min-h-12` targets, no component
library). Introducing shadcn now would fork the visual language mid-project
for a single small indicator. This phase extends the existing system instead.

## Spacing Scale

Declared values (must be multiples of 4), as already used throughout the
codebase:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-glyph micro-gaps |
| sm | 8px | Compact gaps (`gap-2`) between chips/buttons |
| md | 16px | Default element/card padding (`p-4`), the new indicator's padding |
| lg | 24px | Section-internal spacing |
| xl | 32px | Vertical rhythm between major page sections (`gap-8` in `App.tsx main`) |
| 2xl | 48px | Minimum interactive target height (`min-h-12`) — not required for this phase's indicator since it is non-interactive (no button/dismiss), but kept for reference |
| 3xl | 64px | Page-level side gutters at ≥1280px (`xl:px-16`) |

Exceptions: `gap-3` (12px) is already an accepted, in-use exception in this
codebase (`CommandBar.tsx`'s form row) for icon-to-text spacing. The new
indicator reuses this exact exception (`gap-3` between the `BotOff` icon and
the message text) for direct visual consistency with the control immediately
above it — not a new exception, a continuation of an existing one.

## Typography

Full system (existing, reused — not reinvented). This phase's new indicator
uses **only the Body role**.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 18px | 400 (regular) | 1.5 |
| Label (buttons/chips/filters) | 20px | 700 (bold) | 1.2 |
| Heading (h2 section titles) | 24px | 700 (bold) | 1.2 |
| Display (h1 page title) | 32px | 700 (bold) | 1.2 |

**This phase's indicator text is Body role: 18px, weight 400, line-height
1.5.** Deliberately NOT bold — the message is calm, informational status
text, not an alert or a control label. Reserving bold for buttons/headings
elsewhere in the system, and keeping this text at regular weight, is itself
part of the "never alarming" contract (REQUIREMENTS.md, `06-CONTEXT.md`
locked constraint) — a bold, heavier treatment would read as more urgent
than the event (a billing/connectivity issue, not a health emergency)
warrants.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-foam` (`#F2F7F5` light / `#0B1626` dark) | Page background; this phase's indicator surface (card bg) |
| Secondary (30%) | `--color-sky` (`#E2EDF2` light / `#13233A` dark) | Cards, CommandBar's wrapping section, FilterBar surface — the indicator is nested inside this section |
| Accent (10%) | `--color-accent` (`#14213D` light / `#8FC1D4` dark) | Reserved for: Send button fill, active/pressed filter & category-preset chips, the CommandBar working/armed state ring, the Log-out confirm button. **Not used by this phase's indicator** — the indicator is informational, not actionable/selected. |
| Destructive | none — this project has no separate destructive/danger color | Not applicable this phase (no destructive action introduced). Existing precedent: `Header.tsx`'s Log-out confirmation reuses `--color-accent` for its confirm button rather than a red danger color — there is no second semantic color to reuse even if one were needed. |

Accent reserved for: the Send button, active/pressed single-select filter
buttons (date/AM-PM presets), active BP-category chips, the CommandBar's
working/listening state ring, and the Log-out confirm button — an explicit,
closed list. The new liveness indicator is deliberately excluded from this
list by design (D-11's "calm, non-blocking by construction" applies to
color choice, not just copy).

**Explicit prohibition (locked, not a stylistic suggestion):** the indicator
must never use any `--cat-*` clinical category token (`--cat-stage2`,
`--cat-crisis`, etc.). Those colors are reserved exclusively for blood-
pressure clinical severity (`BPTimeline.tsx`, `FilterBar.tsx` category
chips). Reusing a clinical-red for "assistant unavailable" would visually
conflate a billing/connectivity outage with a medical event for a
vulnerable-population user — exactly what REQUIREMENTS.md's "never an
alarming banner" ban and `06-CONTEXT.md`'s locked constraint exist to
prevent.

**Surface logic for the indicator card:** `--color-foam` background with a
2px `--color-ink` border, nested inside the CommandBar section's
`--color-sky` background. This follows the same "alternate surface for
separation" logic already used elsewhere (`ChartSkeleton`'s `bg-sky` tiles
sit on the page's `foam` body background; `Header`'s `bg-sky` buttons sit on
the `foam` header) — here inverted, since the indicator's parent section is
sky, so it uses foam to read as a distinct, separate card rather than
blending into its container.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | None. This phase introduces no new call-to-action button — the indicator is informational-only (D-11: no dismiss, no retry control; it appears/disappears automatically). |
| Empty state heading | Not applicable — no new empty-data state is introduced this phase. |
| Empty state body | Not applicable. |
| Error state (the indicator's one and only message) | **"Assistant unavailable right now — the buttons below still work."** Shown identically regardless of cause (no API key configured vs. every real call currently failing — D-06 locked, no copy branching between the two). Satisfies LIVE-02's required pairing ("assistant unavailable" + "manual controls still work") and Success Criterion 4 (must read distinctly from "didn't catch that" — see Distinctness note below). |
| Destructive confirmation | Not applicable — no destructive action introduced this phase. |

**Distinctness note (Success Criterion 4):** this string must never be
confused with the existing `UNCLEAR_MESSAGE` ("Sorry, I didn't catch that…",
`backend/app/agent/copy.py`), which remains CommandBar's transient message
for a single misheard/misparsed command. The two must keep reading as
obviously different sentences from copy alone — "assistant unavailable"
(infrastructure fact) vs. "didn't catch that" (a specific utterance wasn't
understood) — which the exact strings above already achieve; do not
paraphrase either at implementation time.

**Precedent for a third, independently-authored string:** this codebase
already tolerates two separately-worded "can't reach the assistant" strings
for two different failure moments — `CommandBar.tsx`'s `OFFLINE_COPY`
("Couldn't reach the assistant. The buttons below still work. Try: 'show my
pulse'.", used when a single command's network request fails) and
`backend/app/agent/copy.py`'s `UNAVAILABLE_MESSAGE` ("The assistant isn't
connected right now. The buttons below still work — use them to change the
view.", surfaced via `AgentReply.message` when the agent itself declines).
This phase's indicator copy is a **new, third fixed frontend string**,
worded distinctly from both but consistent in spirit ("still works" framing
carried through). Define it once as a constant (e.g. alongside
`lib/agent.ts` or a small new `lib/copy.ts`) — never inline, never
duplicated with slightly different wording elsewhere.

## Phase-Specific Component Contract

*(Additional detail beyond the standard template — the executor's primary
reference for implementing the one new surface this phase adds.)*

**Component:** `frontend/src/components/AgentStatusBanner.tsx` (name matches
`.planning/research/ARCHITECTURE.md`'s proposed file layout — use this exact
name so planner/executor cross-references resolve cleanly).

**Mount point:** `frontend/src/App.tsx`, inside `Dashboard()`, as a sibling
of `<CommandBar>` — rendered directly below it, still inside the same
`mx-auto max-w-[1280px] px-4 md:px-8 xl:px-16` wrapper `div` (the CommandBar
section):

```tsx
<section className="bg-[var(--color-sky)]">
  <div className="mx-auto max-w-[1280px] px-4 md:px-8 xl:px-16">
    <CommandBar latestReading={latestReading} />
    <AgentStatusBanner />
  </div>
</section>
```

This satisfies D-09 both visually ("near the CommandBar/mic") and
architecturally (a genuinely separate component/DOM subtree — not a branch
inside `CommandBar`'s own status `<p>`, which stays exactly as it is today).

**Scope:** Dashboard only — do not render in `UploadView()`. Upload has no
CommandBar/mic surface (it is an existing mouse/keyboard-only caregiver
flow); the indicator has nothing to sit "near" there.

**Conditional rendering:** the component renders `null` while the assistant
is reachable, and renders the card (below) while unavailable — mirroring
`CommandBar.tsx`'s own established convention of mounting/unmounting its
`aria-live` paragraph rather than keeping it permanently in the DOM with
toggled content. This is a deliberate reuse of an existing in-codebase
pattern, not a new one.

**Markup/styling (exact):**

```tsx
import { BotOff } from "lucide-react";

<div
  role="status"
  aria-live="polite"
  aria-atomic="true"
  className="mt-3 flex items-center gap-3 rounded-lg border-2 border-[var(--color-ink)] bg-[var(--color-foam)] p-4 text-[18px] text-[var(--color-ink)] transition-opacity duration-200 motion-reduce:transition-none"
>
  <BotOff aria-hidden="true" className="h-6 w-6 shrink-0" />
  <span>Assistant unavailable right now — the buttons below still work.</span>
</div>
```

- **Icon:** `BotOff` from `lucide-react` (already installed, confirmed
  present in the pinned version). A crossed-out assistant glyph reads as
  calm/neutral — never a warning triangle, siren, or red octagon icon
  (explicitly banned by `06-CONTEXT.md`'s locked constraint).
- **`role="status"` + `aria-live="polite"` + `aria-atomic="true"`:** correct
  ARIA status-region pattern for a message that changes without direct user
  input. `polite`, not `assertive` — this can appear on page load (LIVE-03)
  without any user action, and `assertive` would interrupt other in-flight
  announcements unnecessarily; every other live region in this app already
  uses `polite`.
- **No dismiss control:** no close button, no "×" icon (D-11, locked).
- **No retry/CTA button:** clearing happens automatically — instantly on
  the next successful real command (D-07) or on the next `/health` poll
  (D-05/D-08). Do not add a "Try again" button here; that pattern already
  exists for the harder, unrelated "couldn't load the readings" failure
  card in `App.tsx`'s `Dashboard` chart region — this is a different,
  softer, self-healing state and must not borrow that pattern.
- **Motion:** `transition-opacity duration-200`, disabled via
  `motion-reduce:transition-none` — mirrors `Header.tsx`'s
  `LogoutConfirmDialog` fade convention exactly. A single calm
  appear/disappear only — never a pulsing, blinking, or looping animation
  (that would itself read as alarming, contradicting the locked "calm,
  non-blocking" constraint).
- **Recovery:** disappears silently — no "assistant is back" success
  message or toast (D-11 — nothing to celebrate, nothing to dismiss).
- **Fail-safe default:** if the `/health` poll request itself errors
  (network failure / backend fully unreachable), treat reachability as
  unknown and show this same indicator rather than silently hiding it —
  fail toward "unavailable," reusing the one fixed string, no new copy
  branch for this edge case.
- **Text/icon color:** `--color-ink` for both — never `--color-accent`,
  never any `--cat-*` token (see Color section above).
- **Sizing:** icon `h-6 w-6` (24px), matching `CommandBar.tsx`'s
  `Mic`/`MicOff` icon sizing exactly. Card padding `p-4` (16px), gap `gap-3`
  (12px, the accepted existing exception — see Spacing section).
- **Width:** full content width (spans the same column as `CommandBar`
  above it) — not a floating toast, not a corner pill. A calm, persistent,
  in-flow element, consistent with the "own distinct, persistent UI
  treatment" PITFALLS.md called for (Pitfall 8's UX-pitfalls table).
