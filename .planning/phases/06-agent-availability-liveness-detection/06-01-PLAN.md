<objective>
Give the backend a passive circuit breaker fed only by real `/agent` traffic outcomes, and thread its verdict into a new `AgentReply.kind == "unavailable"` value and a new `/health` field `agent_reachable`, so the frontend (Plans 02/03) can tell "assistant unreachable" apart from "didn't understand you." No active probe, no new route, no shared rate limit — the breaker is pure arithmetic over module state recorded at the exact site that already observes real Claude call outcomes.

Purpose: LIVE-01 (distinguish unavailable from unclear at the wire level) and LIVE-04 (liveness never spends tokens, never shares /agent's limiter) both resolve entirely in this plan — this is the backend half of Phase 6's wire contract that Plans 02/03 build the frontend against.
Output: `backend/app/agent/service.py` circuit breaker + tuple-returning `call_claude()` + split `interpret()` guard; `backend/app/agent/schemas.py` extended `AgentReply.kind`; `backend/app/main.py` extended `/health`; full backend test coverage (new `test_agent_service.py`, extended `test_health.py`/`test_agent_route.py`).
</objective>
